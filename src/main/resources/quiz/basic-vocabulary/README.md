# Базовая лексика: три универсальных набора

Пакет подготовлен по запросу пользователя: 300 RU→EN, 400 EN→RU и 300 RU→KK.
Аудитория явно UNIVERSAL, классы не назначены. Обратные направления — отдельные
наборы, межнаборные дистракторы выключены. Всего 1000 словарных единиц; некоторые
переводы являются словосочетаниями, а омонимы имеют уточнение учебного смысла.

| Файл | Направление | Количество |
| --- | --- | --- |
| basic-ru-en-300-v1.json | Русский → английский | 300 |
| basic-en-ru-400-v1.json | Английский → русский | 400 |
| basic-ru-kk-300-v1.json | Русский → казахский | 300 |

## Содержание

Первые 300 понятий: семья, люди и профессии, животные, погода, природа, растения,
фрукты, овощи, еда, напитки, дом, мебель, кухня, одежда, тело, школа, город,
транспорт и повседневные предметы. EN→RU дополнен 30 глаголами, 30 прилагательными
и 40 существительными о теле, животных, инструментах и времени.

300 понятий используются в разных направлениях; это не 1000 различных понятий.
Внутри каждого набора исходные слова уникальны после общей нормализации.
Уточнения вроде «лист растения», «замок дверной», `bat (animal)` и `light (weight)`
отделяют разные значения. Синонимы и варианты написания перечислены отдельно от
единственного primary. Эти списки альтернатив требуют редакционной проверки.

## Статус и использование

Это авторский редакционный **DRAFT**, составленный AI, без лингвистической приёмки.
Миграция V54 создаёт из файлов наборы и словарные записи в статусе DRAFT при
следующем обычном запуске приложения с включённым Flyway. Публикации при загрузке нет.
Отдельный импортёр и новые HTTP-маршруты не нужны. В ходе разработки рабочая БД не изменялась.
Перед публикацией редактор проверяет пары, альтернативы и учебные значения,
записывает проверяемый источник и использует обычный workflow банка.

`sourceReference` намеренно пуст: общего адреса словаря недостаточно для заявления
о проверке конкретной пары. Обычная публикационная валидация требует заполнения
источника. Подписи `DRAFT` и отсутствие источника нельзя заменять тестовым аудитом.
Для проверки английских пар подходит [Cambridge English–Russian Dictionary](https://dictionary.cambridge.org/us/dictionary/english-russian/),
для казахских — [Sozdik.kz](https://sozdik.kz/). Ссылки — места для вычитки, а не
подтверждение, что все 1000 пар сверены с этими словарями.

### Как добавить банк в систему

1. Собрать и запустить обновлённое приложение обычным способом. При запуске
   Spring Flyway применит V54 автоматически; вручную переносить JSON не требуется.
2. Войти как администратор и открыть `/admin/vocabulary`. Там появятся три набора
   с кодами из таблицы и 1000 словарных записей вместе с основными и альтернативными переводами.
3. Проверить материал, заполнить источники и провести обычные редакционные переходы
   до публикации наборов и слов. Затем можно создать игры на этих наборах.

Для разработки обычный запуск — `.\gradlew.bat bootRun`; для готовой поставки —
запуск собранного JAR с принятой в среде конфигурацией БД. Gradle `flywayMigrate`
также видит V54 и предварительно собирает классы и ресурсы.
Повторное применение Flyway не дублирует записи и не перезаписывает редакторские изменения.
Если код одного из наборов уже занят, загрузка отклоняется целиком без overwrite.
V54 — Java-миграция Flyway: JDBC получает ID от БД, одинаково на PostgreSQL и H2,
без фиксированных ID и отдельной копии 1000 строк в SQL.

После применения V54 эти JSON-файлы версии v1 не редактируют: их содержимое входит
в checksum миграции. Исправления в установленном банке выполняются через админку;
изменения поставляемого контента — следующей миграцией.

Каждая запись содержит поля существующей формы VocabularyItemForm. Массив
`alternativeAnswers` при вводе через форму переносится по одному переводу на строку;
setId назначается созданным набором. `topicRu` — редакционная группировка файла.
Создание игры после публикации использует WORD_TRANSLATION, направление набора,
UNIVERSAL и выбор класса NONE. Предметные QuestionVersion для слов не создаются.

Четыре варианта формирует существующий VocabularyDistractorService и
VocabularyRoundProvider: один primary и три различных дистрактора того же набора.
В JSON ошибочные варианты не зафиксированы; логика дистракторов не дублируется.

## Автоматическая проверка

BasicVocabularyPackageTest читает все три реальных JSON-файла и моделирует
проверенные версии только в памяти, без записи в БД. Для каждого из 1000 слов
общий provider должен сформировать четыре различных варианта с одним ключом.
Также проверяются направления, количество, явная аудитория, дубли исходных слов
и повтор переводов после общей нормализации. Это проверка формата и движка;
она не подтверждает правильность переводов и не заменяет редактора.

```powershell
.\gradlew.bat test --tests kz.damulab.BasicVocabularyMigrationTest --tests kz.damulab.quiz.engine.BasicVocabularyPackageTest
```

BasicVocabularyMigrationTest проверяет реальный переход V53→V54, совпадение каждой
записи с JSON, сохранение черновиков и альтернатив, повторную загрузку после
редакторского изменения, коллизию кода и полный rollback при ошибке в середине пакета.
Проверки выполняются на случайных синтетических схемах H2/PostgreSQL.
