Вторая: такая же база, затем текущие редакционные сервисы публикуют starter-v1 и текущий QuizRoomService создаёт по пять состояний для SUBJECT_QUIZ, WORD_TRANSLATION и TRUE_FALSE.
ACTIVE намеренно имеет истёкшее серверное расписание, чтобы проверить реальный scheduler. Снимки формируются текущей фабрикой, FINISHED — текущим движком, CANCELLED/EXPIRED — текущими командами.

| Данные до запуска старого JAR | JPA / чтение | Команды и scheduler | Binary возврат |
| --- | --- | --- | --- |
| Только legacy WAITING/ACTIVE/FINISHED после V53 | Читаются; прежний результат сохраняется | Legacy create/start и timeout проверяются | Только для этого проверенного состояния и этого hash |
| Новые WAITING всех трёх типов | JPA/read могут пройти: у WAITING ещё нет раундов | Старый start не знает перенос формирования в start; отказ `room_rounds_not_found` | Запрещён |
| Новые SUBJECT ACTIVE/FINISHED | JPA/read могут пройти благодаря прежнему QUESTION FK | Старый renderer/checker/finish не реализует новый snapshot/time/необратимый ответ; читая ACTIVE, старый сервис способен записать legacy-время null | Запрещён |
| Новые WORD/FACT ACTIVE/FINISHED | JPA строки читаются, renderer падает на nullable QuestionVersion | Старый scheduler способен сохранить ответы без response_ms и новых skip/timeout правил | Запрещён |
| Новые CANCELLED/EXPIRED любого типа | Ошибка `No enum constant ...` | Старый lifecycle отсутствует | Запрещён |

Положительный startup или отдельный GET не доказывает совместимость целиком. В частности, общий результат WORD/FACT может читаться, хотя сама комната не рендерится и scheduler нарушает контракт.
Flag off, переданный старому файлу, не добавляет в него enum/provider/снимки. Матрица не требует удаления новых строк ради успешного запуска старой версии.
Положительная первая строка относится к синтетическому состоянию; она не разрешает автоматический production rollback без QA-06/QA-07 на предназначенной для возврата копии.

## Штатное отключение каталога на новой версии

1. Оставить текущий совместимый binary и V53. Установить `QUIZ_GAME_CATALOG_ENABLED=false` существующим способом конфигурации среды.
2. После reload/restart проверить `/student/quiz`: legacy hub. Новый `/student/quiz/games` и POST карточки недоступны.
3. Проверить уже созданные WAITING/ACTIVE/FINISHED: прямые комнаты, preview/join/ready/start/answer по правам, результаты и scheduler продолжают работать. Действующий JSON create — переходный API; флаг ограничивает каталог/SSR-точку входа, не оркестрацию.
4. Сохранить комнаты/версии/банки/результаты. Не запускать down-migration, Flyway clean/repair или физическое удаление истории.
5. Исправление ошибки поставлять новой версией с выключенным каталогом. Совместимый compatibility build допустим только после собственной полной матрицы.

## Условный binary возврат до новых записей

1. Зафиксировать артефакт и SHA-256; использовать именно проверенный файл, не имя ветки или пересобранный SNAPSHOT.
2. На изолированной мигрированной копии подтвердить состояние первой строки и полный положительный probe, legacy create/start/read/results/scheduler/FK.
3. Если уже есть какие-либо новые игровые записи либо состояние не совпадает с проверенным — **не возвращаться на cb97aac**. Оставить текущий binary с flag off либо поставить исправленную новую версию.
4. Сохранять прежнюю схему и историю. Не очищать данные, чтобы превратить запрещённую ячейку в разрешённую.
5. Производственное переключение выполняется отдельной операторской задачей после QA-06/QA-07; здесь оно не выполнялось.

## Повтор матрицы

При необходимости собрать предыдущий файл: `./scripts/quiz-prepare-previous.ps1`; он печатает путь JAR/hash и сохраняет artifact.json.
Перед использованием контейнера проверить точное имя/label, затем start и заново получить loopback-порт через `docker port`.
Использовать process env QUIZ_TEST_DB_* только для его `quiz_test` по VERIFY_STAGE1.md, плюс `QUIZ_PREVIOUS_JAR` — абсолютный путь выбранного JAR.

```powershell
$env:JAVA_HOME = 'C:\Program Files\JetBrains\IntelliJ IDEA Community Edition 2025.2.6.3\jbr'
$env:QUIZ_UI_SMOKE = $null
# QUIZ_TEST_DB_*: синтетическая изолированная БД, фактический порт docker port.
# QUIZ_PREVIOUS_JAR: конкретный проверяемый файл, не production binary.
.\gradlew.bat quizBinaryRollback --no-daemon --max-workers=1 '-Dorg.gradle.jvmargs=-Xmx256m -Xms64m -XX:MaxMetaspaceSize=192m -XX:ActiveProcessorCount=2 -XX:ReservedCodeCacheSize=64m' -I scripts/quiz-rollback.init.gradle --console=plain
```

Новые схемы имеют случайный префикс quiz_binary_; сохраняются вместе с данными. Старый runtime может нарушить контракт лишь этих синтетических новых комнат — именно это измеряет probe.
Финальный matrix.json и журналы сохраняются в новом ignored `.run-logs/quiz-stage7-rollback-<uuid>/`.
Проверенный отчёт текущего подхода: `.run-logs/quiz-stage7-rollback-8d0b2976-66b5-4500-8bbf-4b6abf3ba3a5/matrix.json`.
После нового содержимого probe зафиксировал 20 ответов до scheduler и 30 после него;
успешное выполнение старого scheduler означает нарушение нового контракта, а не положительную совместимость.
Harness завершает оба application context и старые процессы. После проверок повторно проверить имя/label и остановить только свой контейнер, не удаляя его.
