# Локальная проверка игровых викторин

Из корня `D:\Projects\dlab`:

```powershell
.\scripts\quiz-preview.ps1 -Action Start
```

Открыть `http://localhost:8088/student/quiz`. При первом запуске скрипт закрепляет
собранный bootJar, создаёт свою PostgreSQL-схему и явно публикует starter-v1 и animal-facts-v1 через
обычные редакционные сервисы. Повторный Start сохраняет игры, комнаты и историю;
на работающем стенде повторный запуск отклоняется. Сервер слушает только loopback.
Источник БД — исключительно `quiz_test` контейнера `dlab-quiz-stage1-pg` с проверяемым
label `codex.task=quiz-games-stage1`. Рабочая БД и глобальный флаг не меняются.

## Вход

Учётные данные хранятся локально в ignored `.run-logs/quiz-preview/state.json`:

```powershell
Get-Content .run-logs/quiz-preview/state.json -Raw | ConvertFrom-Json |
    Select-Object host, guest, admin, password
```

- Организатор: `quiz-host@local.test`, 5 класс, RU.
- Гость: `quiz-guest@local.test`, 5 класс, KK.
- Администратор: `quiz-author@local.test`.
- Проверяющий: `quiz-reviewer@local.test`, другой действующий ADMIN; строгая самопроверка включена.

Это локальные проверочные аккаунты; они не создаются при обычном startup проекта.
Для организатора и гостя использовать разные браузеры либо обычное окно и инкогнито.
Пароль одинаковый для этих четырёх аккаунтов, случайный для данного стенда.

## Что пройти

1. На каталоге видны шесть игр: EN→RU, KK→RU, предметная математика, Солнечная система,
   Удивительные животные и Жители океана. У всех есть RU/KK-версии.
2. Завершить solo: 5 раундов по 20 секунд, ответ блокируется после отправки.
3. Во второй сессии открыть приглашение, войти, отметить готовность; организатор стартует.
4. В фактах нажать «Не верю»: это ответ `false`, а не пропуск. Отдельно проверить пропуск.
5. Перезагрузить активную комнату; затем проверить рейтинг, время, личный разбор и повтор.
6. Проверить RU/KK и мобильную ширину. Обязательного речевого прохода нет по решению пользователя.
7. Открыть сохранённые комнаты и результаты после перезапуска стенда.

Предмет остаётся существующей «Математикой», отдельный «Математика: сложение» не создаётся.
Стартовая игра содержит 8 проверенных задач на сложение; происхождение пакета — STARTER_CONTENT.md.
1000 пользовательских basic-vocabulary DRAFT не публикуются автоматически.
В каждой новой игре о животных — 10 утверждений с объяснениями и первоисточниками:
[ANIMAL_CONTENT.md](ANIMAL_CONTENT.md). В одной комнате выбираются 5 утверждений.
Объяснения доступны в разборе после окончания; показ сразу после ответа — будущая работа.

Если стенд подготовлен до добавления animal-facts-v1, остановить его и выполнить
`.\scripts\quiz-preview.ps1 -Action AddAnimals`, затем Start. Эта явная операция
закрепляет новый собранный bootJar и добавляет только две игры, сохраняя схему,
аккаунты и историю. Повторная публикация отклоняется. На новом стенде обе игры
сразу входят в Prepare/первый Start.

## Перезапуск и выключение каталога

```powershell
.\scripts\quiz-preview.ps1 -Action Stop
.\scripts\quiz-preview.ps1 -Action Start -Legacy
```

С `-Legacy` ученический вход показывает прежний раздел; уже созданные новые комнаты
и результаты доступны по прямым ссылкам. Чтобы вернуть каталог на этом стенде:

```powershell
.\scripts\quiz-preview.ps1 -Action Stop
.\scripts\quiz-preview.ps1 -Action Start
```

Статус: `.\scripts\quiz-preview.ps1 -Action Status`.
После проверки: `.\scripts\quiz-preview.ps1 -Action Stop` — останавливает только свой
проверенный Java-процесс и указанный контейнер; данные не удаляются.

## Граница приёмки

Этот стенд готовит локальное пользовательское тестирование. Его свежая отдельная
схема не заменяет QA-06/QA-07 на копии существующей БД dlab. Production-развёртывание
и включение требуют этой проверки и указанного окружения по RELEASE_STAGE8.md.
