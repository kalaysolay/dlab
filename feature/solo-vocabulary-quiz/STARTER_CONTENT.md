# Стартовый пакет starter-v1

Проверка источников: 2026-10-10. Ресурс — `src/main/resources/quiz/starter-v1.json`.
Это учебный контент с фиксированным смыслом, не материал из prototype.js или синтетических test fixtures.
Пакет не загружается при startup/Flyway. Рабочая БД не менялась; публикация проверяется только на изолированных схемах.

## Аудитория и настройки

Все четыре игры адресованы **5 классу**: начальный уровень словаря, повторение арифметики и базовое знакомство с Солнечной системой.
Это авторская редакционная граница стартового пакета, а не заявление о покрытии школьной программы или об универсальной возрастной пригодности.
FIXED_GRADES=[5], NONE, 5 раундов по 20 секунд, 1–4 игрока; изменение count/time запрещено.
Каждый банк содержит 8 пригодных уникальных материалов: запас 3 относительно default/min/max=5.
У каждого слова 7 потенциальных дистракторов из того же языкового набора, требуется 3; cross-set выключен.
Переводы разных числительных и их альтернативы не пересекаются; запрещённые пары не нужны.

| Код | Состав | Направление / формат |
| --- | --- | --- |
| starter-en-numbers-v1 | 8 количественных числительных | EN → RU, TRANSLATION |
| starter-kk-numbers-v1 | 8 количественных числительных | KK → RU, TRANSLATION |
| starter-math-sums-v1 | 8 авторских задач на сложение до 1000 | SUBJECT_QUIZ, SCQ, difficulty=1 |
| starter-space-facts-v1 | 8 утверждений, 4 true / 4 false | TRUE_FALSE, BOOLEAN |

## Слова: сверка каждой пары

## Предметные вопросы

Метод разрядного сложения с переносом сверён по [OpenStax Prealgebra 2e § 1.2](https://openstax.org/books/prealgebra-2e/pages/1-2-add-whole-numbers).
Условия и численные примеры составлены для проекта; не копируются упражнения учебника.
Проверенные равенства: 125+75=200; 348+152=500; 609+91=700; 247+153=400; 560+240=800; 425+175=600; 708+192=900; 134+166=300.
У каждой задачи четыре разных числовых варианта и один ключ, RU/KK-условие и объяснение с тем же равенством.
Суммы проверены независимо от runtime checker; SCQ-публикация проходит обычный QuestionBankService.

Предметная игра использует существующую модель Question/QuestionVersion, без нового предметного банка или копирования старых вопросов.
Подготовлен отдельный предмет «Математика: сложение», поскольку действующий config не фильтрует тему: это гарантирует ровно проверенные 8 источников вместо примеси другого math/grade/type/difficulty.
Это изменение портальной таксономии вынесено пользователю на согласование; до ответа соответствующий итог SEED не объявляется DONE.

## Факты: проверка truth и переводов

Утверждения и объяснения RU/KK сформулированы для проекта. Каждая пара сохраняет один и тот же научный смысл, отрицание и область сравнения.
Күн=Солнце, Жер=Земля, Ай=Луна, Шолпан=Венера; в остальных названиях используется устойчивое международное имя.
Нет меняющегося количества открытых спутников, спорных дат или оценки жизни за пределами Земли.

## Загрузка и предел проверки

`QuizStarterContentService.install(reviewerEmail)` вызывается явно в контексте действующего ADMIN-автора после сверки ресурса; явно указанный проверяющий также должен быть действующим ADMIN.
Самопроверка подчиняется существующей настройке damulab.quiz.strict-self-review; в проверках пакета использованы два разных администратора и strict-self-review=true.
Новые банки и игры выполняют DRAFT → NEEDS_REVIEW → APPROVED → PUBLISHED. Предметный банк сохраняет свой существующий путь createQuestion(DRAFT) → approve → publish; для approve используется контекст проверяющего. Сервисы сохраняют действующие audit ID автора/проверяющего. Самовызова при запуске, миграции или ученика нет; отдельный публичный endpoint не добавлен.
Коллизия кодов отклоняет всю загрузку без overwrite существующих редакций. Ошибка источника/публикации откатывает пакет целиком. Настройка каталога не меняется.
В этой поставке install исполняется только тестами и rollback-harness на собственных синтетических схемах. Загрузка в рабочую среду — отдельная операторская работа после приёмки, вне текущего запроса.

`QuizCompatibilityIntegrationTest` публикует именно этот ресурс при strict-self-review=true и проверяет каждую игру в solo / 4 игрока, RU/KK, ответы по закрытым серверным снимкам, 100%, 5 личных разборов с объяснениями и источниками, завершение scheduler при flag off.
Это подтверждает исполнимость и достаточность данного пакета; не заменяет речевую UI-10-приёмку или работу QA-06 с production-копией.
