# Foundation: принятые контракты и техническая граница

Дата: 2026-10-09. Основание продуктовых решений: пользователь явно выбрал «Принять пакет рекомендаций» из §§ 2.1/2.4 плана. Техническая фиксация `ARCH-01` выполнена в рамках начала этапа 1; это не подтверждение готовности кода/миграционной регрессии.

## 1. Продуктовые решения

- Самопроверка конфигурируется; audit автора/проверяющего сохраняется всегда. Для MVP строгий запрет выключен по умолчанию, новый ADMIN-role не создаётся.
- Неполный профиль даёт заблокированную карточку с исправимой причиной. Полностью недоступный по политике класс не обходится.
- Count/seconds по умолчанию фиксированы, изменяются только при явном разрешении версии в заданных диапазонах. Соло — та же комната; первый принятый ответ/skip окончателен; skip/timeout в ничьей полный лимит.
- Политики аудитории § 8 сохраняются без упрощения. Универсальность явная, классы всех участников проверяются сервером.
- Retention: автоматического удаления нет. SRS, награды, late join, runtime AI и повтор только ошибок не входят в MVP.
- Полный перевод служебного интерфейса админки не обязателен в первой поставке; ученические поля/сообщения RU/KK обязательны.
- `catalog_visible` принадлежит стабильной игре; default true не публикует DRAFT. Скрытие запрещает новые create/replay, но не start/join прежней WAITING при остальных проверках. Архив игры/источника блокирует start; комната остаётся WAITING до cancel/expiry, ACTIVE/FINISHED читаются по снимкам.
- Fallback метаданных: локаль пользователя → RU → другая доступная; blank равно отсутствию; нет обязательного заголовка нигде — безопасная недоступность + admin diagnosis. Новые обязательные переводы публикации не заменяются fallback.

## 2. Схема и порядок миграций

Существующие V1–V46 не изменяются. Последующие номера назначаются по фактической ветке, без слияния с чужими миграциями задним числом.

1. **V47, первый инкремент:** `quiz_games`, `quiz_game_versions`, subject config/types и version grades. Составные FK `(game_id, version_id)` запрещают чужие published/draft pointers. Версия имеет собственный редакционный status; появление draft не меняет доступность прежней публикации. Видимость и её audit на стабильной игре. Положительные version_no, count/time ranges и max_players 1–4 ограничены БД.
2. **Банки:** словарные sets/set_versions/items/item_versions/answers/grades/exclusions и fact sets/statements/versions/grades по § 13. Published/draft pointers принадлежат своему владельцу; ссылки опубликованной истории restrict, не cascade. Audit FK на app_users nullable для system seed/удалённого автора, переходы редактора всё равно записывают пользователя.
3. **Оставшиеся typed configs:** word/fact config только с настоящими FK на банки. Один PK game_version_id; тип источника согласован с game_type через fixed discriminator + составной FK. Предметные вопросы не копируются. Эти таблицы не имитируются отсутствующими FK в V47; `DB-01` целиком закрывается лишь после них.
4. **Rooms / rounds / answers:** nullable game/version/type для legacy; expires/cancelled, settings_revision default 0; participants ready_revision для stale-ready защиты. Idempotency — отдельное соответствие `(student_profile_id, key_hash)` комнате + payload_hash, не секретный raw token в логах. Пока нет удаления комнат, автоматического TTL-удаления ключей тоже нет. Новые round sources соответствуют content_kind, ровно один FK; legacy QUESTION и snapshots nullable на переходе. У новых ответов response_ms, skipped и timed_out; legacy время не выдумывается.
5. **Индексы и ограничения:** FK/unique/check, индекс доступных карточек/банка/аудитории и room expiry. Максимум один primary у слова обеспечивается переносимо: внутренний nullable `primary_marker` в vocabulary_item_answers, значение 1 только у primary, NULL только у альтернатив; CHECK согласует marker/is_primary, UNIQUE(version_id, primary_marker) запрещает два primary. Обязательное наличие одного primary проверяется публикационным сервисом. Маркер не является редактируемым пользовательским полем. Это позволяет не зависеть от несовместимого с H2 partial-index синтаксиса; ограничения отдельно проверяются на PostgreSQL. JSON — только снимки/ответы, не произвольная редактируемая конфигурация.

Версионирование источников и snapshot защищают историю; запрет редактирования опубликованного и проверка полноты типовой конфигурации дополнительно обеспечиваются будущими сервисами публикации. Наличие таблицы или enum не даёт права создавать/публиковать неполную игру.

## 3. Команды и время

- Create фиксирует published game version, создаёт только WAITING/host. Idempotency scoped учеником + create, разные payload одного ключа конфликтуют. Code retry ограничен десятью попытками; повтор после unique violation выполняется в валидной новой транзакционной попытке. Trim/case/алфавит едины, старые коды поддерживаются.
- Settings: `POST /api/quiz/rooms/{code}/settings`, host + WAITING; gradeId, разрешённые questionCount/roundSeconds, expected settingsRevision. Lock, сверка revision, аудитория присутствующих и достаточность. Изменение увеличивает revision и сбрасывает guest ready, host готов. Ready подтверждает revision; stale ready/settings конфликтуют. SSR-команда вызывает тот же сервис с CSRF, не отдельные правила.
- Start под room lock читает окончательный состав и текущие published версии заданного банка. Публикация набора и отбор на старте должны дать согласованную редакцию; ID источников, использованная конфигурация набора, locale, варианты, ключ, объяснение/источник сохраняются. Изменение банка после старта не читается игровым checker.
- Отдельные неопубликованные черновики не блокируют пригодный опубликованный состав; непроверенный материал в опубликованной выборке запрещён. Диагностика/start используют одну трактовку. Публикация первого качественного слова не требует уже опубликованных дистракторов; четыре варианта обязательны для игры.
- Content locale фиксируется комнатой при create из допустимой локали организатора, при старте не меняется; условия и порядок одинаковы, UI-подписи участников персонально локализуются. Для предметного банка используется соответствующий QuestionVersion language; нет fallback на случайный иной учебный источник.
- Answer: ID текущего раунда + либо typed answer, либо skipped=true. False валиден. MCQ canonical comparison по множеству IDs, MATCHING по парам; FILL_IN не получает новую семантику через произвольную нормализацию retry. Окно `[start, end)` серверное; нет позднего grace для нового режима. Skip окончателен. Timestamp принятия и tie-break вклад — разные понятия: skip/timeout всегда полный лимит.

## 4. Сервисы, подписки и rollback

Используются компоненты § 14 спецификации; существующий QuizService остаётся переходным фасадом. Публичная модель чтения текущего раунда отдельно от закрытого снимка. События после commit, без ответов/ключей; HTTP — источник состояния.

STOMP inbound проверяет principal/STUDENT/exact topic/membership, SEND и wildcard запрещены. Для существующего simple broker нужен контроль исходящей доставки по session/subscription + текущему membership, а не только SUBSCRIBE: leave отзывает доступ всех вкладок. Гонка leave/delivery проверяется в SEC-ROOM-01. Если этот транспорт нельзя защитить, запуск использует авторизованный polling, не открытые подписки.

Flag off на новой версии — штатное отключение точки входа с сохранением новых комнат/результатов/scheduler. Предыдущий бинарный файл после новых типов/статусов не считается совместимым автоматически. COMP-04 фиксирует конкретный artifact + состояние БД и runbook; без положительной проверки возврат на него запрещён. Используется новая исправленная версия/проверенный compatibility build, без удаления истории/down-migration.

## 6. Реализованная основа (2026-10-10)

- V47 — игры/версии и subject config; V48 — словарный банк и word config; V49 — утверждения и fact config; V50 — добавочные поля комнаты/раунда/ответа. V1–V46 не изменены.
- JPA-основа находится в `kz.damulab.quiz.catalog`: отдельные enum, стабильные сущности, версии и типовые конфигурации. `@MapsId` связывает PK config с версией; составные FK проверяют механику и направление перевода. Общие mapped superclass содержат ID/редакционный статус и аудит создания, проверки и публикации.
- Audit хранит ID пользователей с настоящими FK, без загрузки аккаунта при чтении каждой карточки. В банках/версии игры используются `grade_id`, в профильной аудитории комнаты — `grade_no`; это разные ключи, их преобразует сервис. Коллекции классов возвращаются только для чтения и заменяются копией.
- Репозитории не реализуют редакционный workflow: публикация, полнота primary/переводов/config и неизменность опубликованного проверяются сервисами этапов 2–3. CRUD и заполнение published_at сами по себе не являются разрешением публикации.
- Каталог загружает published version через EntityGraph одним SQL. Config/варианты переводов/исключения доступны пакетными запросами. Word/fact count и ID-выборка используют одинаковый предикат публикации, архива и пересечения всех требуемых классов; пустая аудитория допускает только явно universal-материал.
- Room repository содержит lock по каноническому регистру кода и ограниченную выборку истёкших WAITING. Сервисные проверки прав/settings/start/answer, сброс готовности всех гостей и подключение expiry scheduler остаются этапом 5; один репозиторий этого не реализует.
- Раунд хранит типизированные FK и закрытый снимок; legacy QUESTION без снимка остаётся читаемым. Снимок фиксируется до первого сохранения, проверяется целиком до присваивания и не перезаписывается. DTO безопасного текущего раунда/сериализация/checkers — этап 4; закрытый ключ нельзя выдавать через entity serialization.
- В новых ответах доступны response_ms/skip/timeout; legacy response_ms остаётся null. Уровень модели отклоняет повторную запись времени, баллы за skip/timeout и replace новой игры. Серверное окно, канонический retry и tie-break рассчитывает движок следующих поставок, не foundation.
- TEST-DB-01 использует пустую базу и контролируемую V46-фикстуру с WAITING/ACTIVE/FINISHED, ответом и результатом; дополнительно приложение стартует поверх этой старой схемы и читает историю через JPA. Это не реальная production-копия: QA-06 с её объёмами/особенностями остаётся отдельной предпусковой задачей.
- Подробные команды, opt-in memory profile и границы проверки: [VERIFY_STAGE1.md](VERIFY_STAGE1.md). Фактические итоги и оставшиеся задачи — GAP.md/§ 29 спеки.

Пессимистическая блокировка стабильной игры и обязательная revision защищают save/review/approve/publish/archive/visibility. Новое сохранение создаёт отдельную редакцию и сбрасывает проверку; первая публикация фиксирует code/type.

Чек-лист страницы не является разрешением публикации.
- `QuizGameContentDiagnostics` загружает все три источника и классы пакетно. `VocabularyDistractorService.Dataset` переиспользует ту же policy без SQL на каждое слово/игру. Публикационный минимум проверяется по худшему составу; default/max-дефицит — подтверждаемое предупреждение. Финальная проверка фактической комнаты остаётся обязательной.

Диагностика требует оба текста; UNIVERSAL для SUBJECT_QUIZ получает ошибку вместо вывода универсальности из пустых gradeLinks. Доступны политики класса/участников, без копирования предметных вопросов в новый банк.
- `QuizContentEligibility` централизует полноту и аудиторию. Повреждённый/неподтверждённый опубликованный состав блокирует игру; отдельные новые черновики не влияют на действующие публикации. Отсутствие дистракторов исключает слово как вопрос, не запрещает наполнение банка.
- `QuizGameAvailabilityPolicy` проверяет новую комнату/replay по текущей видимой публикации, а WAITING start — по закреплённой версии без проверки hide, но с запретом архивированного источника/игры. - SSR `/admin/quiz-games/**` включает список/фильтры, форму, контент, checklist и предпросмотр только карточки/правил RU/KK. GET не создаёт редакции или комнаты, ключи ответов в шаблоны не передаются. ADMIN/CSRF/escaping и ограниченное число SQL подтверждаются тестами. Небольшой JS только показывает источник выбранного типа, не меняет бизнес-правила.
- Относящаяся к админке часть UX-03 описана в `flow/GAME_ADMIN_CONTRACT.md`; прежние макеты исправлены, демонстрационные действия отключены. Остальные экраны UX-03 не закрыты.

## 9. Контракты движка (этап 4, 2026-10-10)

Код расположен в `kz.damulab.quiz.engine`. Это серверные компоненты без новых маршрутов, команд комнат, STOMP или ученического UI. Каталог остаётся выключенным. `QuizService` обслуживает прежний предметный режим своим существующим контрактом.

- `QuizRoundProvider.prepare(room, requiredGradeIds)` возвращает уникальные ID текущих опубликованных версий и закрытые сборщики. Провайдеры ничего не сохраняют; они вызываются внутри транзакции фабрики. Fact/Subject SQL ограничен выбранным набором/предметом. Для слов `VocabularyDistractorService.prepareForGame` ограничивает SQL набором либо языковой парой при explicit cross-set opt-in; опубликованность и policy совпадают с диагностикой. `QuizContentEligibility` используется для полноты и пересечения аудитории всех классов.
- `QuizRoundFactory.create(code)` блокирует существующую WAITING-комнату, повторно проверяет закреплённую публикацию/источник и настройки, читает фактические классы профилей, выбирает уникальные источники и собирает весь набор до INSERT. `saveAllAndFlush` и снимок аудитории входят в одну REPEATABLE_READ-транзакцию. Повтор формирования запрещён. Переход ACTIVE отсутствует: будущий start должен вызвать фабрику в своей общей транзакции после проверки host/expiry/ready и только затем зафиксировать startedAt/status. Ошибка дальнейшего шага откатывает и уже сохранённый набор.
- UNIVERSAL передаёт пустой requiredGradeIds только как explicit policy; пустые классы источника не становятся универсальными. SUBJECT + UNIVERSAL отклоняется явно. PARTICIPANT_GRADES/FIXED_GRADES записывают фактические номера всех участников; ROOM_GRADE записывает выбранный класс и повторно запрещает младшему ученику более старшую комнату. Без требуемого класса профиля формирование запрещено.

### 9.1. Формат снимка

Существующие V50-колонки используются без новой миграции. `QuizRound.snapshot` присваивает полный набор один раз до сохранения; JPA snapshot-колонки `updatable=false`. Все порядки фиксируются до первого INSERT и больше не перемешиваются при чтении.

| Формат | `options_snapshot_json` (публичная часть) | `answer_key_snapshot_json` (закрытая часть) |
| --- | --- | --- |
| SCQ / MCQ | Массив `{id, text}`; id — прежний label, text — локаль комнаты; массив перемешан | Прежний массив правильных label |
| MATCHING | Объект `{left: [{id,text}], right: [{id,text}]}`; колонки перемешаны независимо; id — прежнее RU-значение | Прежний `{pairs:[{left,right}]}` |
| FILL_IN | `{placeholders:["[[1]]", ...]}` без правил и значений | Прежние правила по placeholder: `{answer,mode,tolerance?}` |
| TRANSLATION | Четыре `{id,text}`; после перемешивания текстов назначаются A–D, правильный ID не имеет постоянного положения | JSON-строка выбранного правильного ID |
| BOOLEAN | `[true,false]` | JSON boolean, включая полноценный `false` |

`source_config_snapshot_json` содержит `format` и `sourceVersionId`; SUBJECT дополнительно `subjectId,difficulty`, VOCABULARY — `setVersionId,sourceLanguage,targetLanguage,pronunciation`, FACT — `setId`. Это закрытая метаинформация снимка, не произвольная конфигурация игры. Условие, локализованное объяснение, проверяемый источник и локаль хранятся в отдельных колонках. Предметные варианты копируются по белому списку, без isCorrect/ключей/служебных полей банка. Обязательные RU/KK-тексты публикации проверяются; fallback применяется к необязательному разбору/метатексту, а не заменяет обязательный учебный перевод.

### 9.2. Проверка и время

`QuizRoundAnswerChecker` читает только снимок. Предметный адаптер вызывает перегрузку `AnswerChecker.check(type,keyJson,answer,ONE)` без JPA-версии. Payload сохраняет прежние предметные структуры: `{selected:[ids]}` (SCQ/MCQ), `{pairs:{left:right}}`, `{answers:{placeholder:text}}`; перевод использует `{selected:[id]}`. Для FACT содержимое answer — JSON boolean непосредственно. Подписи интерфейса не являются протоколом. Отсутствие/null/строка `"false"` не становятся boolean false. Skip передаётся отдельно, совместное содержательное значение запрещено.

Канонический retry сравнивает множества MCQ и нормализованные пары MATCHING по прежним правилам checker; FILL_IN сохраняет текст буквально и сортирует только имена полей. `QuizAnswerEvaluator` создаёт несохранённую запись принятого ответа или явного skip внутри `[start,end)` и timeout после end. Он записывает серверную метку принятия и `response_ms`; skip/timeout не приносят баллов. Сохранение первого ответа, уникальность/retry/conflict и гонка с timeout остаются ответственностью командного сервиса этапа 5: evaluator не перезаписывает существующий ответ и сам не выполняет INSERT.

### 9.3. Безопасное чтение и результаты

`QuizCurrentRoundReader.read(code,profileId,now)` проверяет membership и возвращает `{status,totalRounds,serverTime,currentRound}`. `currentRound` содержит только ID/номер/format/prompt/options/locale/presentation, startsAt/endsAt и собственный `answered`. `presentation` ограничена sourceLanguage/targetLanguage/pronunciation. WAITING, FINISHED и время вне окон не возвращают условие. Коллекции будущих раундов, ключи, источник, explanation и isCorrect отсутствуют в типе DTO. Сервис не сериализует JPA.

`QuizResultCalculator` начисляет ровно один балл за правильность по снимку; процент округляется HALF_UP, как в существующем режиме. Рейтинг: score ↓, сумма response_ms ↑, joinedAt ↑; ID служит последним стабильным порядком при полностью одинаковых значениях. Skip/timeout/неотвеченный раунд дают полный лимит, независимо от технического answeredAt и раннего skip. Legacy response_ms остаётся null, прежний сервис/рейтинг не переключаются на новый движок и не получают ретроспективное время. Для нового содержательного ответа отсутствие достоверного времени считается ошибкой, а не нулём.

`QuizGameResultService.save` идемпотентно сохраняет результаты уже FINISHED-комнаты под блокировкой; не завершает lifecycle сам. `read` допускает только участника FINISHED-комнаты и возвращает его строку, публичную таблицу и только собственный разбор. Разбор содержит condition/options/answer, correct, skipped/timedOut, responseMs, correctAnswer, explanation и sourceReference; FILL_IN выдаёт правильные значения без технических rule/mode/tolerance. Банки/профили не используются для проверки или восстановления текста после старта. Подключение этих DTO к HTTP, правам principal и комнатному lifecycle — этап 5.

## 10. Команды универсальной комнаты (этап 5)

`QuizRoomService` обслуживает новые комнаты отдельно от legacy `QuizService`, а `QuizApiController` является переходным фасадом на прежних HTTP-путях. Новый create принимает только gameCode/gradeId/count/seconds/idempotencyKey; subjectId-формат продолжает прежний контракт. Каталог и новый ученический UI не включаются. Прямой legacy renderer/checker не допускает новые комнаты, legacy scheduler пропускает их.

Каждая новая команда выполняется в собственной REQUIRES_NEW/REPEATABLE_READ транзакции. Под обычным PESSIMISTIC_WRITE room lock сервис дополнительно запрашивает PESSIMISTIC_FORCE_INCREMENT уже заблокированной строки. V53 вводит @Version command_revision: изменения только participants/answers тоже обнаруживаются устаревшим snapshot. Прямой FORCE_INCREMENT query на PostgreSQL использовал NOWAIT и был заменён на два шага после реальной конкурентной проверки. Optimistic/serialization failures повторяют всю транзакцию до пяти попыток; затем безопасный ROOM_BUSY. settings_revision остаётся пользовательской редакцией правил, начинается с 0 и меняется только при существенной настройке.

Create блокирует профиль ученика, хранит SHA-256 ключа и нормализованного набора параметров атомарно с room/host. Коллизия unique откатывает всю попытку и повторяется в новой транзакции (до 10), включая гонку после двух exists=false. Повтор ключа возвращает прежнюю комнату независимо от дальнейшего скрытия игры; другой payload даёт IDEMPOTENCY_CONFLICT. Вместимость/тип/банк/locale берутся сервером. WAITING timeout задаётся damulab.quiz.waiting-timeout (default 30m, env QUIZ_WAITING_TIMEOUT); flag каталога не отключает действующие комнаты.

Join/settings проверяют общую eligibility/provider-достаточность по фактическому составу, start повторяет проверку и сохраняет полный batch + ACTIVE/startedAt. После формирования batch срок WAITING проверяется повторно перед фиксацией startedAt: истечение во время формирования откатывает все раунды, последующий scheduler переводит комнату в EXPIRED. Гости подтверждают settingsRevision; изменение сбрасывает их ready, host остаётся ready. null/отсутствие настройки при settings сохраняет текущее значение; PROFILE_DEFAULT применяется при create. Leave гостя и cancel host доступны в WAITING; ACTIVE сохраняет участников. Терминальные комнаты остаются в истории. Replay — обычный create актуальной опубликованной версии, прежние участники не переносятся.

Первый answer/skip окончателен; canonical retry сравнивается до проверки текущего окна и допустим после его закрытия/FINISHED. Timeout не перезаписывает ответ. Scheduler и state/results догоняют расписание из startedAt, заполняют отсутствующие прошедшие ответы и завершают только после полного лимита всех раундов. Finish и сохранение результатов составляют одну транзакцию. Никаких grace/speed bonus в новом режиме; legacy grace и история сохранены.

`QuizGameRoomResponse` сохраняет прежние имена полей комнаты и расширяет их game metadata, capabilities/blockers, expiry/settings revision/flags/ranges. Будущие rounds содержат только orderNo/startsAt/endsAt; currentRound берётся из безопасного reader этапа 4. Preview до join содержит только title/organizer/count/max/status/canJoin/blocker. Results — общий рейтинг и только свой разбор. Все новые ошибки имеют code/message RU/KK, разрешённые details — только численность доступного/необходимого контента.

`QuizRoomEventPublisher` фиксирует только type/code/status/occurredAt и отправляет после commit. room.round_changed выдаётся при переходе общего серверного окна даже если все ответили; ограниченный памятью активных комнат реестр подавляет повторные сигналы, после рестарта разрешён безопасный повтор. Этот реестр не управляет временем/finish. HTTP остаётся источником истины.

`QuizRoomSubscriptions` защищает точный канонический topic, аутентификацию/STUDENT и membership. SEND/wildcard/чужие назначения запрещены; endpoint доступен STUDENT, Origin остаётся same-origin. Outbound ExecutorChannelInterceptor проверяет актуальное участие непосредственно перед handler и удерживает read-lock до завершения доставки. Leave удерживает write-lock через commit и отзыв всех подписок этого user/room до последующих доставок; queued сообщения, другие вкладки и reconnect проверены. Реестр очищается при DISCONNECT. Это защита существующего simple broker в одном процессе; распределённый broker/кластер не вводится этой поставкой.

## 11. Ученический UI (этап 6)

`QuizStudentCatalog` пакетно читает текущие опубликованные версии, конфигурации и общую
диагностику. Видимость, аудитория и пригодность используют существующие policies;
карточки содержат только метаданные, допустимые классы и ключ идемпотентного POST.
`QuizStudentPageController` отдаёт Thymeleaf-оболочки после проверки membership.
Классы WAITING читаются из закреплённой версии; replay выбирает актуальную публикацию.
JPA-сущности и закрытые снимки не сериализуются в ученический HTML.

Новые входы `/student/quiz/games` и POST карточки требуют game-catalog-enabled;
`/student/quiz` сохраняет legacy вход при false. `/student/quiz/join`, уже созданные
комнаты и результаты доступны независимо от переключения. Флаг по умолчанию false;
формальная приёмка совместимости и binary rollback относятся к этапу 7.

`quiz-game-core.js` формирует typed ответы всех форматов, различает false/null,
считает серверное время и пороги 10/5. `quiz-games.js` меняет DOM через textContent,
использует CSRF HTTP-команды и state; STOMP только сигнализирует обновление. Polling
3 секунды и reload восстанавливают состояние. Неподтверждённый ответ сохраняет один
payload для retry; после принятия выбор блокируется. Условия будущих раундов,
правильность и объяснение появляются только через разрешённый серверный DTO.
Результат показывает рейтинг и собственный разбор; повтор создаёт отдельную комнату.

CSS ограничен новым UI и использует app-shell/app.css: 360 px, цели 44×44,
видимый фокус, aria-describedby, polite live region только для порогов, reduced motion.
MVC проверяет права/CSRF/безопасные оболочки; Node + jsdom проверяют реальный клиентский
DOM без рабочей БД. Браузерный проход использует только синтетический RANDOM_PORT
test-сервер. Речевая проверка настоящим скринридером ещё открыта: UI-10/UX-03 не DONE.
