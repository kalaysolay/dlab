# Каталог игр и универсальная комната

Стартовая страница: `index.html`. Макет полностью статический, сервер Node.js не нужен.

Требования для реализации, включая отличия от ранних макетов, зафиксированы в [SPECIFICATION.md](../SPECIFICATION.md).

Пользовательские цели и приёмка: [USE_CASES.md](../USE_CASES.md) (37 сценариев). Порядок поставок, подготовленные контракты для ревью и матрица покрытия: [IMPLEMENTATION_PLAN.md](../IMPLEMENTATION_PLAN.md). Спецификация v0.3 включает уточнения видимости, пропуска, STOMP, кодов, локализации и отката; сами демонстрационные страницы ещё требуют `UX-03` и не считаются исправленной реализацией.

## Основной маршрут

`Игры → готовая карточка игры → предыгровая комната → начать игру`.

Ребёнок не выбирает режим «один» или «с друзьями». Любая игра создаёт комнату минимум для одного участника. Приглашение друзей остаётся необязательным действием на экране запуска.

## Кликабельные страницы

- `index.html` — каталог готовых игр и вход по коду.
- `room.html?game=english` — слова на английском; класс не выбирается на экране, но может использоваться для безопасной выборки.
- `room.html?game=kazakh` — слова на казахском; класс не выбирается на экране, но может использоваться для безопасной выборки.
- `room.html?game=math` — математика; класс берётся из профиля и может быть изменён.
- `room.html?game=facts` — «Верю / не верю»; класс не используется.
- `join.html` — короткий вход приглашённого игрока по коду.
- `room.html?game=english&mode=guest&code=QZ7K2M` — состояние гостя, который ждёт организатора.
- `word-game.html`, `subject-game.html`, `true-false-game.html` — три игровые механики.
- `result.html` — результат игры.
- `states.html` — индекс ключевых сценариев и пограничных состояний.

## Администрирование

- `admin-quizzes.html` — список игр, фильтры, статусы и готовность контента.
- `admin-quiz-edit.html` — карточка игры, локализации, политика класса и правила комнаты.
- `admin-quiz-content.html` — выбор банка и безопасные правила отбора контента.
- `admin-quiz-publish.html` — проверка готовности, ученический предпросмотр и публикация.
- `admin-word-bank.html` — банк слов с аудиторией, источником и статусом модерации.
- `admin-word-edit.html` — слово, допустимые переводы, классы и источник.
- `admin-fact-bank.html` — отдельный банк утверждений, наборы и редакционные статусы.
- `admin-fact-edit.html` — RU/KK-текст, boolean-ключ, объяснения, источник и явная аудитория.

Для поставок 2–3 закрыта часть `UX-03` для банков и административной публикации: классы/явная универсальность, формы утверждений, отдельные редакции, две политики, лимит 1–4, видимость и архив. [GAME_ADMIN_CONTRACT.md](GAME_ADMIN_CONTRACT.md) фиксирует правила форм, диагностики и POST. Противоречивый демонстрационный JS на четырёх игровых административных страницах отключён; числа остаются подписанным статическим примером. Отмена/истечение комнаты и полная a11y-приёмка ученических экранов остаются открытыми.

Выбор класса в комнате и безопасная аудитория контента задаются раздельно. Минимум участников равен одному, поэтому одиночная и совместная игра используют один и тот же жизненный цикл комнаты.

Все страницы используют существующие `app.css`, `fonts.css` и `lucide-sprite.svg`, поэтому визуальные решения можно перенести в текущие шаблоны без создания отдельной дизайн-системы.

Ход серверной реализации, остаток и проблемы ведутся в [GAP.md](../GAP.md); статические страницы не являются доказательством выполнения кодовых задач.

Принятые технические контракты и границы реализованной основы — [ARCHITECTURE.md](../ARCHITECTURE.md); команды H2/PostgreSQL-проверок этапа 1 — [VERIFY_STAGE1.md](../VERIFY_STAGE1.md).

## Реализация ученического UI этапа 6

Рабочие шаблоны расположены в `src/main/resources/templates/student/quiz-game-*`
и `quiz-games.html`, клиент — `static/js/quiz-game-core.js` и `quiz-games.js`.
Каталог, host/guest, preview, SCQ/MCQ/MATCHING/FILL_IN, word/fact, собственный разбор,
replay и CANCELLED/EXPIRED работают поверх серверного API. Демонстрационный
`prototype.js` не задаёт выборку, проверку ответа, время или правила комнаты.

В реальном браузере проверены solo, две независимые сессии, RU/KK, 360 px,
клавиатура, фокус и reload; клиентские regression-тесты проверяют offline retry,
пороги 10/5 и отсутствие ранней обратной связи. Ручной речевой проход с настоящим
скринридером пока не выполнен. UX-03 остаётся IN_PROGRESS; этап 7 не начат.
