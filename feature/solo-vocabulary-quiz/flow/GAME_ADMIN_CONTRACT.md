# Контракт экранов административной публикации — часть UX-03

Страницы `/admin/quiz-games`, `/new`, `/{id}/edit`, `/{id}/content`, `/{id}/publish` используют существующий admin-layout. Демонстрационный JS не переносится в приложение.

- Список различает опубликованную редакцию, текущий черновик и независимую видимость. Фильтры: поиск, тип, статус, RU/KK, наличие ошибок. Счётчики рассчитывает сервер пакетными запросами.
- Форма сохраняет общие и типизированные настройки одной командой. Код и тип фиксируются первой публикацией. Минимум игроков всегда 1, максимум 1–4; late join не настраивается. Только ограниченный набор существующих стилей, без произвольного CSS/JSON.
- Отдельные поля `grade_selection_mode` и `audience_policy`. ROOM_GRADE требует PROFILE_DEFAULT/REQUIRED и непустые разрешённые классы. PARTICIPANT_GRADES требует NONE. FIXED_GRADES требует непустые классы. При NONE/UNIVERSAL список пуст, но универсальность задана явно политикой.
- Контент: опубликовано → подходит аудитории → пригодно, причины и ссылки к материалам. Для ROOM_GRADE проверяется каждый разрешённый класс отдельно; для FIXED_GRADES/PARTICIPANT_GRADES — допустимые сочетания классов до max_players. По монотонности достаточно сочетаний максимальной мощности; диагностика показывает худшее покрытие, а не сумму несовместимых выборок. Пустая аудитория UNIVERSAL допускает только явно универсальные материалы. У предметных вопросов нет признака universal: такую пригодность нельзя выдумывать из пустого списка классов.
- Минимальная достаточность блокирует публикацию; недостаток для default/max — предупреждения с явным подтверждением. Только опубликованный проверенный состав, черновики не блокируют действующую публикацию. Для слов недостаток трёх дистракторов исключает слово из пригодных вопросов.
- Публикация: draft → review → approved → published; повторная серверная проверка POST. Предпросмотр показывает только карточку и правила RU/KK, не создаёт комнату и не содержит ключей ответов.
- Все команды передают revision игры. Устаревшая форма/действие получает ошибку и требует перечитать текущую редакцию. Новое сохранение создаёт отдельную редакцию, прежняя проверка не переносится.
- Скрыть/вернуть — отдельный POST с аудитом. Скрытие запрещает новые create/replay, сохраняет join/start прежней WAITING. Архив блокирует новые create и start; история остаётся. Общая серверная policy будет подключена к HTTP комнат в этапе 5, сами команды комнат здесь не создаются.
- Видимость и редакционный статус имеют текстовые подписи, формы имеют label/legend, ошибки не зависят от цвета; все пользовательские тексты экранируются.

UX-03 выполнена для банков и административной публикации игр. Комнатные состояния cancel/expiry и полная приёмка ученических экранов остаются открытыми.
