# 3. План реализации

Статус: проект v0.2. Основной канал — мобильный веб/PWA без APK. Созданы [HTML-макеты](../../redesign/english-speaking/README.md), реализованы [текстовый каркас](IMPLEMENTATION.md) и [локальное распознавание голоса](VOICE_IMPLEMENTATION.md). Собеседник остаётся stub. Этап 3 реализован в коде, но физические Android/iPhone, установленная PWA и качество на детской речи ещё требуют приёмки. Остальные этапы ниже описывают целевую реализацию; их готовность не следует из готовности этих срезов.

## Этап 0. Проектирование и изоляция работы

Результат: отдельная ветка `feat/english-speaking`, четыре основных документа, каталог ситуаций и промпты с проверками.

Готовность: документы согласованы друг с другом; явно разделены требования, предположения и решения до пилота; текущий незавершённый код других доработок не затронут.

До перехода к продуктовой реализации уточнить сценарные цели и объём MVP. D-01…D-06 из бизнес-требований можно закрывать по мере подхода к зависимому этапу; для макетов внешний провайдер и денежный лимит не нужны.

## Этап 1. Кликабельные макеты — созданы

На синтетических данных, без настоящего микрофона и отправки чего-либо ИИ. Сначала полноценный мобильный путь для браузера и PWA на Android/iOS, затем desktop. Следовать существующему стилю DamuLab. Базовые макеты — 360/390/430 CSS px, проверка компактного экрана от 320 CSS px; одноколоночная компоновка, крупные действия записи, safe-area и состояние с открытой клавиатурой обязательны.

| Экран/состояние | Что можно проверить кликом |
| --- | --- |
| Каталог | Пять ситуаций, краткие цели, переход к вводной, краткая история |
| Вводная | Роли, сложность, язык объяснений, обработка речи, старт/продолжение |
| Разговор | Вопрос, прослушивание и замедление, запись, таймер, остановка, отмена |
| Остановка записи | Сразу автоматическая отправка на распознавание; пока идёт обработка — понятный статус, без отдельной кнопки «Распознать» |
| «Я услышал…» | Подтвердить, исправить текст, перезаписать, прослушать запись, неуверенное распознавание |
| Обычный ответ | Короткая реакция ИИ, следующий вопрос, раскрытие исправления |
| Помощь | Опорные выражения и упрощённый вопрос, возврат к тому же ходу |
| Возврат к теме | Первое отклонение, повторное отклонение, продолжить/сменить/завершить |
| Безопасное ограничение | Нейтральный отказ от неподходящего продолжения без показа исходного текста |
| Поддерживающая пауза | Отдельное спокойное состояние без грамматической проверки |
| Ошибки | Нет разрешения на микрофон, тишина, сеть, TTS, непроверенный ответ, лимит |
| Телефон и PWA | Отказ/отзыв разрешения, сворачивание, звонок/блокировка, возврат, утрата неотправленной записи, восстановление отправленного ответа, открытая клавиатура |
| Итог и история | Короткий итог, продолжение практики, удаление сессии |

Готовность: можно пройти от каталога до итога и все ветви ошибок без тупика; ребёнок понимает, когда его записывают, что отправлено и как выйти. Текстовые подписи и плотность исправлений проверены с владельцем продукта. Макет обозначен как демонстрация; симуляция не выдаётся за реальный ИИ.

## Этап 2. Каркас модуля без внешних запросов

- Пакет `speaking`, флаги доступа, роли и проверка владельца.
- Миграции собственных таблиц; номера выбрать по актуальному состоянию ветки перед реализацией.
- Каталог пяти сценариев и фиксация их версий в сессии.
- Модель состояний, session/turn DTO, лимиты, идемпотентность, stub-провайдеры.
- Первый сквозной текстовый путь: старт → ответ → итог → история.
- Сразу создать собственную `speaking_observations` и провести запись замечания через stub вместе с принятием хода. Учебная память входит в первый рабочий срез; её нельзя отложить до создания подробного экрана аналитики на этапе 5.
- Локализация ru/kk для интерфейса и объяснений; английские реплики в обоих вариантах.

Готовность: проверки ролей, чужого ID, CSRF, флага, одного активного диалога, повторного запроса и завершения проходят без сети. Отдельный пакет не меняет поведение тестов/викторин/переводчика.

## Этап 3. Браузерная запись и распознавание

Сначала синтетическое аудио/stub ASR. Реальная обработка детского голоса — после D-01 и D-02.

- Определение поддерживаемого формата; запись ≤60 s / ≤10 MB; остановка capture на выходе.
- Автоматическая отправка на распознавание после остановки (также по лимиту 60 секунд), временное хранение и «Я услышал…» с прослушиванием, правкой и перезаписью.
- Очистка временных файлов при успехе, ошибке, удалении и аварийном завершении.
- Текстовый путь, неясная речь, тишина, превышение размера, занятый микрофон и потеря сети.
- Проверка микрофона, поддерживаемых кодеков и воспроизведения на физическом Android/iPhone в браузере и установленной PWA до фиксации реального ASR-адаптера. Выбранный серверный путь должен принимать форматы обеих платформ либо иметь проверенное ограниченное преобразование.
- Жизненный цикл телефона: прерывание записи звонком, сворачиванием и блокировкой; восстановление с сервера; явный повтор без фоновой отправки. Отдельно ошибка проигрывания после сетевого ожидания.
- Измерение ASR на детской английской речи с акцентом и ошибками: отрицание, окончания, неправильные формы глаголов. До разрешения реальных данных — актёрские/синтетические примеры.

Готовность: голосовой путь проверен на физических Android/iOS в браузере и PWA, затем на Windows; спорное распознавание не создаёт учебных ошибок; аудио отсутствует в постоянной БД, логах и PWA-кэше. Работа только в desktop или переход на текст вместо голоса на телефоне не закрывает этап.

## Этап 4. Управляемый диалог и безопасность

Реальные адаптеры — только после D-03 и D-04 и допуска соответствующей обработки данных.

- Общий промпт и пять сценарных инструкций; версия конфигурации фиксируется в сессии.
- Структурированный ответ модели и серверная валидация.
- Проверка входа и всех отображаемых полей выхода; локальные fallback и отдельная поддерживающая пауза.
- Контроль переходов, двух отклонений, количества ходов, подсказок и инъекций.
- Проверенная озвучка готовой реплики; повторное прослушивание без нового диалогового вызова.
- Сначала контрольные en/ru примеры, затем обязательная проверка kk и смешанного ввода.

Готовность: набор проверок из приложения пройден; нет критических нарушений; отключение/сбой guard закрывает генерацию безопасно; отказ провайдера и невалидный JSON не попадают ученику в сыром виде.

## Этап 5. Учебные наблюдения и итог

- Исправления с привязкой к подтверждённому тексту и фиксированному навыку.
- Развить уже включённое на этапе 2 сохранение наблюдений: чтение повторяющихся трудностей, честные статусы `observed`/`recurring`, оспаривание. Проверить атомарность с ходом, отсутствие дублей и невозможность записать наблюдение другому ученику.
- Отделение ошибки от стилистической альтернативы, помощи, ручной правки и сбоя распознавания.
- История, итог без дополнительных обязательных LLM-вызовов, удаление и TTL.
- Для следующей сессии до двух подходящих повторяющихся навыков; без объявления освоения по одному ответу.
- Полный пересчёт затронутых агрегатов после оспаривания/удаления.

Готовность: минимум 50 замечаний проверены человеком; семантика счётчиков воспроизводима; школьная `skill_mastery` не изменяется; удаление действительно убирает цитаты и производные данные.

## Этап 6. Качество, расходы и эксплуатация

- Выбор допустимых ASR/LLM/TTS/guard по единому набору качества и условий обработки.
- Тайм-ауты, резерв бюджета, квоты, идемпотентные повторы, метрики этапов, деградация при сбоях.
- Проверка, что существующий `AiCallLogger` с выдержками пользовательского содержимого не используется для speaking.
- Проверка отсутствия текста в логах и сторонней аналитике, приватных данных в кэше и пользовательских файлов в публичном static.
- Уточнение D-05, D-06, процедуры удаления из рабочих данных и резервных копий.
- Прогон 10 одновременных активных сессий и 5 параллельных обработок как стартового нагрузочного профиля пилота; больший масштаб вне заявлений MVP.
- Мобильный сетевой профиль NFR-20, перезапуск/выгрузка страницы, Wi-Fi → мобильная сеть, открытие с иконки PWA, обновление service worker и восстановление после истечения сессии. Зафиксировать устройства, ОС, версии браузеров и режим запуска в отчёте.

Готовность: достигнуты или явно пересмотрены до пилота цели задержки; известна стоимость по всем этапам; сервер отказывает до нового вызова при исчерпанном бюджете; есть аварийное отключение.

## Этап 7. Ограниченный пилот

Условия: закрыты D-01…D-06, необходимые дополнения baseline зафиксированы, тестовый набор пройден, флаги включены только для разрешённой группы. Наличие макетов и рабочих stub-тестов этих условий не заменяет.

1. Первое занятие с наблюдением взрослого и возможностью сразу прекратить запись.
2. Добровольная практика в течение 1–2 недель.
3. Разбор полезности, интереса, распознавания, ложных исправлений, задержки и расходов.
4. Исправление обнаруженных проблем; решение о расширении пилота.

Критическое нарушение безопасности или приватности: выключить внешние вызовы, ограничить доступ к затронутым данным, разобрать причину и повторить соответствующий набор проверок до повторного включения. Автоматического массового запуска нет.

## Проверки при реализации

После каждого реализованного вертикального среза: подходящие unit/integration проверки и пробная сборка `.\gradlew.bat build` по правилам репозитория. Не запускать реальные платные запросы в обычном CI.

| Группа | Минимум |
| --- | --- |
| Контракт | DTO, состояния, ссылки на сценарии, лимиты, отсутствующие/неизвестные поля ответа LLM |
| Доступ | Роль, владелец сессии/хода/аудио, CSRF, флаги, allowlist |
| Надёжность | Повтор ключа с тем же/другим телом, гонка вкладок, истёкший процесс, тайм-аут, перезагрузка клиента |
| Приватность | Логи, кэш, временные файлы, удаление/пересчёт, исходящие DTO, реальный статус запрета внешних вызовов |
| Учебный смысл | Цитата, ложное исправление, навык из allowlist, помощь, пустая речь, стиль, ручная правка |
| LLM-оценка | Все пять ситуаций × три сложности; многоходовые отклонения; обязательные критические случаи из приложения |
| UI | Полный голосовой путь, текстовый путь, клавиатура, мобильная ширина, разрешения, аудиоплеер и ошибки |
| Мобильная PWA | Физические Android/iPhone, браузер + установленная PWA, звонок/блокировка/сворачивание, системная клавиатура, safe-area, медленная/пропадающая сеть, обновление SW без потери активной записи |

## Зависимости и риски

- **Ошибки распознавания:** обязательное подтверждение, отдельный учёт источника; не обещать проверку произношения.
- **Скучный разговор:** не фиксировать дословную последовательность вопросов; оценивать реакцию на смысл и повторяемость при пилоте.
- **Избыточные исправления:** максимум два на ход, необязательное раскрытие, человеческая проверка ложных замечаний.
- **Prompt injection и взрослые темы:** несколько слоёв, fail-closed, версии и повторные проверки при замене модели/промпта.
- **Голос и существующий baseline:** отдельное решение до данных, а не попытка объявить голос анонимным.
- **Зависимость от чужой доработки:** основа — `40bb69d`; нужные последующие изменения основного проекта переносить осознанно перед реализацией, без копирования текущей грязной папки.

Оценку в рабочих днях давать после макетов и выбора допустимой голосовой конфигурации: эти решения существенно меняют объём.
