## Принятые для проектирования предположения

- Модуль внутри DamuLab с общей авторизацией, отдельным пакетом `speaking` и собственными данными.
- Основной канал — телефон: мобильный браузер и установленная на главный экран PWA DamuLab на Android/iOS. Весь голосовой путь работает без APK и без обязательной установки PWA; desktop — дополнительный канал.
- Разговор по одной выбранной ситуации: вопрос текстом с озвучкой, голосовой ответ, короткое исправление, следующий вопрос.
- Один режим MVP; исправления можно раскрывать, но они не прерывают диалог обязательным упражнением.
- Учебные замечания с первого рабочего диалога сохраняются в собственной таблице `speaking_observations`; по повторениям модуль определяет трудности. Школьные таблицы оценок и mastery не используются для хранения этих фактов. В текущем HTML-макете БД нет — это обязательное требование к реализации.
- Первая аудитория пилота — школьники примерно 10–14 лет с английским A2–B2. Это рабочая гипотеза, а не результат определения уровня дочери пользователя.
- Стандартная сессия: цель 8 содержательных ответов, предел 12 принятых ответов, ориентир 5–10 минут.
- Новые реплики озвучиваются автоматически целиком (реакция и вопрос), есть выключатель и ручное повторение. Запись включается только по явному действию. [Изменения после проверки на телефоне](MOBILE_VOICE_UPDATE.md).
- Первый этап после обсуждения документов — кликабельные макеты на синтетических данных.

Числа в требованиях — предлагаемые стартовые настройки и критерии пилота. Они не являются измерениями текущего приложения или обещанием качества конкретной модели. Изменение этих настроек отражается одновременно в требованиях, спецификации и проверках.

## Важные решения до реального пилота

1. Подтвердить аудиторию и механизм разрешения доступа несовершеннолетним; класс не использовать как доказательство возраста.
2. Выбрать допустимую схему обработки голоса и текста. Действующий [AI Safety Baseline](../../docs/AI_SAFETY_BASELINE.md) запрещает передачу персональных данных внешним ИИ. Удаление имени не делает голос обезличенным.
3. Явно описать применимость baseline к живому диалогу: правило ручного одобрения учебного контента нельзя молча считать выполненным для автоматически показываемых реплик.
4. Утвердить провайдеров для пилота по результатам проверки детской речи, безопасности, задержки, условий хранения и стоимости. Проверенные технические конфигурации и стартовые резервы уже записаны в [этапе 6](OPERATIONS_IMPLEMENTATION.md); это не заменяет допуска реальных детских данных.

Эти решения не блокируют документы, заглушки и макеты. До их выполнения реальные внешние вызовы для детских сессий выключены.

## HTML-макеты

Макеты сначала проектируются для телефона: портретная ориентация, крупные действия записи, экранная клавиатура и безопасные отступы. Они должны покрыть каталог, вводную ситуации, разговор, подсказку, подтверждение распознавания, исправление, возврат к теме, безопасный ответ, ошибки микрофона/сети, прерывание звонком/блокировкой, возвращение в приложение, завершение и краткую историю. Подробный перечень переходов приведён в плане реализации.

Разговор требует сети и открытого на экране приложения. Фоновая запись и офлайн-ИИ в MVP не входят. После возвращения восстанавливается принятый сервером прогресс; сохранность неотправленной записи после выгрузки страницы системой не обещается.

HTML-макеты созданы отдельно в общей папке [redesign/english-speaking](../../redesign/english-speaking/README.md). Они включают главную ученика с входом в разговорник и демонстрационный путь до итога. В этом пакете требований нет кода приложения, миграций или реальных вызовов моделей.

## Продуктовая реализация

Реализованы [текстовый срез](IMPLEMENTATION.md), [голос](VOICE_IMPLEMENTATION.md) и [живой диалог](LIVE_IMPLEMENTATION.md): отдельный пакет speaking, собственные таблицы с реальным сохранением и страница ученика. Это приложение Spring Boot, отдельное от автономных HTML-макетов. STT использует Deepgram; LLM выбирается в общей админке OpenAI/DeepSeek; озвучка — OpenAI. Локальный стенд оставлен с DeepSeek `deepseek-flash`, STT и TTS. Код опубликован на production; [отчёт](PRODUCTION_DEPLOYMENT.md).

## Проверка пакета

Проверены локальные ссылки, парность блоков кода, синтаксис четырёх JSON-блоков, ограничения примера TURN по приведённой схеме, точность цитаты исправления, уникальность ID требований и отсутствие пробелов в концах строк. Проверка JSON выполнена локальным Node.js-скриптом по используемым ограничениям, без внешнего валидатора JSON Schema. Это проверка документов, не проверка поведения модели.

Для технического среза этапа 6 прошла полная `gradlew.bat build i18nVerify`: 525 тестов без падений/ошибок/пропусков, 551 ключ ru/kk. Проверены синтаксис `speaking.js` и приватная cache-policy service worker. Живой корпус, PostgreSQL, контейнер и оставшаяся приёмка описаны в [подготовке релиза](RELEASE_PREPARATION.md). Предыдущие результаты этапов 4/5 сохранены в соответствующих отчётах.
