# Подготовка релиза разговорника

4 ноября 2026. Первоначально публикация была отложена до разбора структуры сервера. После настройки SSH код `7c3d29d` опубликован; фактические пути, проверки и команды сохранены в [отчёте о выкладке](PRODUCTION_DEPLOYMENT.md). Ниже сохранена подготовка релиза; ветка не сливалась в основную.

## Что подготовлено

- Runtime Dockerfile включает ffmpeg для мобильных WebM/M4A; Java 21, сборка bootJar. `.dockerignore` исключает `.env*`, build, Git, макеты и QA-артефакты из контекста. Ключи и синтетические аудиофайлы не входят в образ.
- `docker-compose.prod.yml` и `.env.prod.example` передают отдельные speaking-флаги, Deepgram и бюджет. По умолчанию модуль, облачный диалог, STT и TTS выключены; pilot-only=true. Секреты остаются в защищённой серверной конфигурации.
- V71 добавляет бюджетную таблицу и nullable provenance без переписывания старых цитат. Перед применением на общей ветке нужно проверить свободные номера миграций и совместимость с её изменениями; уже применённую миграцию нельзя переименовать/редактировать на работающей БД.
- Локальный preview: `http://127.0.0.1:18084/student/speaking`, отдельная файловая H2 `build/qa/speaking/preview-data`; тестовые сессии переживают рестарт. Это синтетический стенд, не копия production. Его ключи подключаются только из игнорируемого файла конфигурации.

## Репетиция восстановления и удаления

На отдельной PostgreSQL 16.15 в локальном Docker создана синтетическая БД: 1 speaking-сессия, 2 наблюдения, 17 записей `quiz_games`. `pg_dump` восстановлен в отдельную тестовую `speaking_restore`: количества совпали. Удаление всех `speaking_sessions` **только в восстановленной тестовой копии** каскадно оставило 0 сессий / 0 наблюдений и сохранило 17 `quiz_games`. Восстановление не проверялось на production-дампе.

Рабочие сроки: текст ходов очищается после 30 дней; замечания с цитатами и метаданные сессий имеют предел 180 дней; расчёт повторов использует окно 30 дней. Удаление своей истории убирает собственные сессии, ходы, наблюдения, ASR-черновики, leases и TTS-кэш; дневные квоты/резервы не обнуляются. Аудио хранится только временно, штатно очищается в finally, аварийно — плановой очисткой. Политика внешнего хранения, offsite-копий и их TTL пока не проверена.

**Восстановление старого дампа может вернуть уже удалённые цитаты.** До открытия восстановленного приложения нужно сверить удаления и дневные расходы; если достоверного журнала удалений нет, безопасный вариант для согласованного восстановления — очистить speaking-историю в восстановленной копии, сохранив остальные модули, и держать облачные флаги закрытыми до сверки квот/бюджета. Репетиция подтверждает каскад именно этой операции. Это не команда автоматически очищать данные при старте и не разрешение удалять production-историю. D-06 должен определить постоянную процедуру и срок жизни копий до пилота.

## Порядок будущей выкладки

1. Подтвердить production-хост, структуру каталогов, владельца процессов, действующую БД/volumes, CI/deploy и reverse proxy. Не подменять неизвестную схему новым compose-проектом поверх работающего приложения.
2. Согласовать ветку с актуальной основной, проверить миграции; сохранить точную версию старого образа и защищённую конфигурацию. Получить свежую резервную копию БД и файловых volumes; проверить восстановление в изолированной копии.
3. Собрать образ без ключей, проверить ffmpeg и production-профиль на изолированной PostgreSQL. При первом запуске оставить speaking-флаги выключенными; Flyway должен применить только ожидаемые миграции, demo-пользователи не должны появиться.
4. Выкатить согласованным серверным способом; проверить вход ученика/админа, существующие уроки/переводчик, закрытый speaking, приватный кэш и отсутствие исключений. Не использовать Flyway clean/repair как обход ошибки релиза.
5. Отдельно закрыть приёмку из [этапа 6](OPERATIONS_IMPLEMENTATION.md), проверить доступность/срок жизни моделей и выбрать маршрут SPEAKING в общей админке: локальный стенд использует DeepSeek deepseek-flash; для OpenAI бюджетный допуск теперь gpt-4.1-mini. Старый gpt-4o-mini не допускается по умолчанию из-за ложных исправлений на QA; сохранённый маршрут БД автоматически не переписывается. Включить модуль только для разрешённой группы. Ключи не вставлять в команды, журнал и документацию.

Аварийно сначала выключить `SPEAKING_CLOUD_ENABLED`, `SPEAKING_VOICE_ENABLED`, `SPEAKING_SPEECH_ENABLED`; для закрытия раздела — `SPEAKING_ENABLED=false`. Для обычной env-конфигурации потребуется пересоздание/рестарт приложения; уже отправленный запрос может завершиться и расходовать резерв. Общий `AI_REAL_PROVIDERS_ENABLED=false` отключает облако и других функций, поэтому применять осознанно.

V71 аддитивна; откат приложения на предыдущий образ оставляет новые таблицу/колонки. Совместимость старого Flyway с более новой схемой нужно проверить на копии; не обещать безусловный rollback одним переключением тега. Возврат всей БД из дампа — отдельное согласованное восстановление с риском потери новых данных и возврата удалённых цитат. Готового production-отката пока нет, поскольку структура сервера отложена на отдельную задачу.
