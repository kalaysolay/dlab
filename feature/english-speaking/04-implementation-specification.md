# 4. Спецификация реализации

Статус: проект v0.2; основной клиент — мобильный браузер/PWA без APK. Имена новых классов, таблиц и API ниже — целевой контракт, а не утверждение об их наличии в коде. Требования — в [02](02-functional-nonfunctional-requirements.md), ситуации — в [05](05-scenario-catalog.md), промпты — в [06](06-ai-prompts-and-evaluation.md).

## 4.1. Основа и границы модуля

Проверенная основа ветки `40bb69d`: Java 21, Spring Boot 3.3.7, Spring MVC/Thymeleaf, Security, JPA, Flyway, PostgreSQL. Уже существуют `ai`, `translator`, `analytics`, `parentlink`, `users`, версионируемые `AiPromptService`/`AiPromptCode` и runtime-настройки `AiRuntimeSettingsService`.

Существующий `AiProvider` ориентирован на генерацию учебного контента и перевод. Голосовые методы не добавлять к нему только ради общего интерфейса. Использовать отдельные небольшие адаптеры speaking. `AiCallLogger` пишет выдержки запросов/ответов; для ученических диалогов он непригоден без изменения поведения. Speaking использует собственные логи только метаданных.

Целевая структура:

```text
kz.damulab.speaking
  SpeakingPageController / SpeakingApiController
  SpeakingSessionService       — доступ, сценарий, состояния, квоты
  SpeakingTurnService          — запись, подтверждение, принятие результата
  SpeakingScenarioCatalog      — опубликованные версионированные карточки
  SpeakingPromptService        — сборка ограниченного модельного контекста
  SpeakingSafetyService        — локальные правила, guard, безопасные шаблоны
  SpeakingFeedbackService      — валидация замечаний и учебные наблюдения
  SpeakingBudgetService        — резервирование и учёт расхода
  TranscriptionProvider / TutorProvider / SpeechProvider / ContentGuard
  Stub... и реальные адаптеры — только по мере выбора конфигурации
```

Без очереди сообщений, отдельного сервиса, Redis и потокового WebRTC в MVP. Сервер обрабатывает запрос синхронно с ограниченным тайм-аутом; короткими транзакциями фиксирует начало и результат операции. Это позволяет клиенту восстановить состояние после потери HTTP-ответа.

HTML: `templates/student/speaking/{catalog,session,history}.html`; вводная и итог могут быть состояниями этих страниц. JS: `static/js/speaking.js`, стили в отдельном ресурсе с использованием существующих токенов. Не менять существующие игровые движки, переводчик и формулу школьного mastery.

В текущем `manifest.webmanifest` уже задан `display: standalone`, а `service-worker.js` исключает `/student/**` и `/api/**` из кэширования. Использовать эту основу PWA и проверить её при добавлении speaking; новый APK, отдельное мобильное приложение или обязательная установка не нужны. Описания baseline в документации не заменяют проверку фактического service worker.

## 4.2. Конфигурация

Предлагаемые новые ключи:

```yaml
damulab:
  speaking:
    enabled: false
    pilot-only: true
    external-enabled: false
    external-audio-enabled: false
    target-turns: 8
    max-turns: 12
    max-audio-seconds: 60
    max-audio-bytes: 10485760
    max-text-chars: 2000
    max-sessions-per-day: 3
    max-audio-seconds-per-day: 900
    session-idle-minutes: 30
    temporary-data-ttl-minutes: 15
    transcript-retention-days: 30
    observation-retention-days: 180
```

Пилотный допуск — серверный, связан с аккаунтом и записью необходимого разрешения, не с переданным браузером возрастом. Пока D-01/D-02 не закрыты, допустим только synthetic/stub-режим. При неизвестном возрастном допуске реальный режим закрыт; номер класса не заменяет проверку.

Модели/guard и цена конфигурируются сервером независимо по ролям ASR, TUTOR, TTS, GUARD. Для TUTOR можно добавить `SPEAKING_TUTOR` в существующие `AiUsageType` и формы настроек. ASR/TTS не заставлять использовать `AiProviderCode`, пока не выбран поддерживаемый набор. Любой реальный адаптер проверяет флаги speaking и общий `real-providers-enabled`. Денежные потолки на ученика/день и модуль/день обязательны до включения внешнего режима; значения не определены этим проектом.

Обычные настройки и модель закрепляются в снимке сессии, чтобы результаты были воспроизводимы. Аварийный флаг, отзыв допуска провайдера и новая обязательная safety-политика имеют приоритет над снимком: старую сессию остановить, предложить новую после обновления, не продолжать с устаревшими ограничениями.

## 4.3. Данные

Публичные ID — случайные UUID. Владение проверяется через текущего авторизованного ученика, а не через переданный `studentId`. Локальные ID и UUID не входят в исходящий модельный контекст.

| Таблица | Основные поля и инварианты |
| --- | --- |
| `speaking_sessions` | `id`, `student_profile_id`, `scenario_code`, `scenario_version`, снимок карточки, `level`, `explanation_language`, версии промптов/политики, допустимая конфигурация моделей, `status`, `stage`, выполненные цели, `accepted_turns`, `meaningful_turns`, `off_topic_streak`, `audio_seconds`, `created_at`, `last_activity_at`, `finished_at`, `version` для optimistic locking |
| `speaking_turns` | `id`, `session_id`, `sequence_no`, `source` (`voice`/`typed`/`edited`), `status`, минимизированный подтверждённый текст, `audio_duration_ms`, `recognition_quality` (`unknown`/`uncertain`/`usable`), признак подтверждения, проверенные поля реакции/вопроса/feedback, `disposition`, `operation_lease_until`, версия guard, времена. Аудиобайта или публичного пути нет |
| `speaking_observations` | `id`, `student_profile_id`, `session_id`, `turn_id`, `skill_code`, `kind` (`error`/`style`), допустимые фрагменты original/corrected, объяснение, `evidence` (`suggested`/`confirmed`/`disputed`), источник ответа, признак помощи, `created_at`, `expires_at`; уникальность `(turn_id, skill_code, original, corrected)` |
| `speaking_requests` | Ученик, endpoint/action, хеш idempotency key, хеш тела, состояние `in_progress`/`succeeded`/`failed`, ссылка на результат, `lease_until`, время. Не хранит сырые payload/аудио; TTL 24 h. Ключ не отправляется провайдеру |
| `speaking_usage` | Локальный request/operation ID, этап, провайдер/модель/версия цены, зарезервированный/учтённый расход, единицы usage, время, код результата; без текстов и аудио. Для дневной квоты связывается локально с учеником |

Каталог ситуаций хранится в версионированных ресурсах `speaking/scenarios/*.json`, проверяемых при запуске; миграции БД для редактора не нужны. Промпты используют существующее версионирование там, где оно подходит: новый код `SPEAKING_TUTOR`, снимок системной версии в сессии. Обязательная safety-политика — ресурс приложения, не произвольное поле ученического запроса.

Индексы: владелец/статус сессии; владелец/дата истории; session/sequence; observation/skill/date; usage/student/date. Частичный unique index не допускает две сессии `ACTIVE`/`PAUSED_SUPPORT` у одного ученика. Номера Flyway выбрать перед реализацией: в соседней рабочей папке уже есть незакоммиченные миграции, поэтому заранее резервировать V64 и последующие нельзя.

Не создавать таблицу агрегированного speaking mastery в MVP: повторяющиеся ошибки вычислять по наблюдениям. Сырые тексты удаляются по TTL независимо от срока наблюдений; фрагменты в наблюдениях тоже являются данными и имеют собственный TTL. После удаления сессии её наблюдения удаляются каскадно; остальные рекомендации пересчитываются запросом.

При обычном истечении 30-дневного TTL диалога очищаются его тексты, а минимальные метаданные сессии/хода, необходимые для ссылочной целостности наблюдений, сохраняются до истечения наблюдений (проектно 180 дней). Явное удаление пользователем — другой путь: удаляются также связанные наблюдения, без сохранения их ради статистики.

## 4.4. Состояния

Сессия:

```text
ACTIVE → COMPLETED        — достигнуты цели и минимум 6 содержательных ответов,
                            обычно около 8; либо серверный предел 12 ответов
ACTIVE → ENDED            — ученик закончил раньше
ACTIVE → PAUSED_SUPPORT   — обнаружено сообщение о реальной опасности
PAUSED_SUPPORT → ENDED    — выход; автоматического возобновления упражнения нет
ACTIVE/PAUSED_SUPPORT → EXPIRED — 30 минут без действий или отзыв допуска
```

Причина завершения хранится отдельно (`goals_reached`, `turn_limit`, `student_finished`, `idle`, `access_revoked`). `COMPLETED` по лимиту не означает, что все учебные цели достигнуты. После поддержки можно выйти в каталог и осознанно начать новую ситуацию; приложение не требует объяснять личное событие.

Внутреннее состояние хода:

```text
TRANSCRIBING → AWAITING_CONFIRMATION → GENERATING → READY
TRANSCRIBING → ASR_FAILED
GENERATING → GENERATION_FAILED
любой ещё не принятый → DISCARDED
неподходящий/чувствительный вход → REJECTED
```

Текстовый ввод начинает с `AWAITING_CONFIRMATION` после локальной проверки. До `READY` он не увеличивает число принятых ответов. Неподтверждённая расшифровка живёт только во временном защищённом хранилище ≤15 минут; в постоянной таблице до подтверждения — метаданные, не сырой текст. При истечении предложить перезапись/ввод заново.

`READY` включает обычный ответ и безопасный возврат к теме. `disposition` определяет, можно ли учитывать его как содержательный и создавать наблюдения. Опасный/чувствительный вход не хранится дословно, а получает `REJECTED`, локальный результат перехода и минимальную категорию. Ошибки обработки не являются учебными результатами.

## 4.5. API

База: `/api/student/speaking`. Все методы — STUDENT + владелец + флаг/пилотный допуск; CSRF для POST/DELETE. Создание, распознавание и приём ответа принимают `Idempotency-Key` (UUID клиента). Изменение текущего вопроса проверяет `expectedVersion`. Повтор одного ключа с другим телом — 409. Ниже — фактический контракт этапов 2–5; проектные расширения не выдаются за работающие маршруты.

| Метод и путь | Вход | Результат |
| --- | --- | --- |
| `GET /scenarios` | — | Опубликованные карточки и допустимые сложности без закрытого системного промпта |
| `POST /sessions` | `scenarioCode`, `level`, `explanationLanguage` | 201: сессия и заранее проверенный первый вопрос выбранного уровня; повтор ключа возвращает тот же ресурс |
| `GET /sessions` | — | Последние 20 сессий текущего ученика; курсор пока не реализован |
| `GET /sessions/{id}` | — | Состояние, версия, проверенные реплики, `focusSkills`; у завершённой сессии локальный `summary` |
| `GET /difficulties` | — | Независимые наблюдения за 30 дней: observed/recurring, частота разных ходов/сессий |
| `POST /sessions/{id}/transcriptions?expectedVersion=…` | Аудио в теле, Content-Type audio/* | Черновик ASR, ID, текст, длительность и TTL; квота до ASR |
| `POST /sessions/{id}/turns` | JSON: `text`, `expectedVersion`, необязательный `voiceAttemptId` | 201: обновлённая сессия после подтверждения/проверки; источник voice/edited назначает сервер |
| `DELETE /sessions/{id}/transcriptions/{attemptId}` | — | Отбросить черновик; расход ASR не сбрасывается |
| `POST /sessions/{id}/help` | `expectedVersion` | Сценарная подсказка; следующий ответ assisted, повтор открытия не увеличивает счётчик |
| `POST /sessions/{id}/speech` | `turnId` (null для первого) | MP3 серверного вопроса; normal/slow — playbackRate одного Blob в браузере |
| `POST /sessions/{id}/observations/{observationId}/dispute` | `expectedVersion` | Замечание исключено из рекомендаций и итога; разрешено также для завершённой сессии |
| `POST /sessions/{id}/finish` | `expectedVersion` | Идемпотентное завершение и локально собранный итог |
| `DELETE /sessions/{id}` | — | 204: сразу закрыт доступ, рабочее удаление/очистка по NFR-05 |
| `DELETE /sessions` | — | 204: вся собственная история и производные данные, включая записи за пределами первых 20; квоты сохраняются |

Исходящий ответ — DTO `SpeakingViews.Session`: `version`, `status`, `acceptedTurns`, `providerMode`, доступность голоса/озвучки, полная последовательность `turns`, `observations`, до двух `focusSkills`, необязательный `summary`. В turns есть disposition, reactionText/questionText; UI выводит действия по статусу. Сырые ответы провайдера, системный промпт и внутренние диагностические строки браузеру не отдаются. Во всех приватных ответах `Cache-Control: no-store`.

Ошибки: `400` невалидный ввод/код сценария; `403` нет роли/допуска/CSRF; `404` чужой/удалённый ресурс или выключенный модуль; `409` конфликт версии/активная сессия/операция/ключ с другим телом; `413` размер; `415` неподдерживаемое аудио; `422` тишина/непригодное распознавание; `429` квота/бюджет с временем сброса; `503` провайдер/guard недоступен; `504` тайм-аут. Формат: `{ "code": "speaking_asr_unavailable", "retryable": true }`; локализованный текст берётся из интерфейсных ресурсов. Содержательные ограничения возвращаются как безопасное состояние, а не как техническая ошибка.

## 4.6. Обработка голосового ответа

До первого голосового ответа `POST /sessions` возвращает начальную реплику ИИ: приветствие, краткий ввод в выбранную ситуацию и один вопрос. Вход ученика для этого не нужен. Реплика фиксируется как сообщение собеседника, не увеличивает `accepted_turns` и видна до предложения записать ответ. Пока начальная реплика не готова, показывать «Собеседник начинает разговор…» и не предлагать ребёнку говорить первым. Озвучка доступна по кнопке. После готовой реплики — «Теперь твоя очередь», короткое пояснение на языке интерфейса и начальная опорная фраза; это помощь при старте, не учебная ошибка.

1. Клиент запрашивает микрофон после нажатия. Выбирает формат через `MediaRecorder.isTypeSupported()`; при отсутствии поддерживаемого формата предлагает текст. Базовые кандидаты — WebM/Opus и MP4/AAC; сервер принимает только реально поддержанные адаптером контейнеры/кодеки.
2. Запись ≤60 s; видимый таймер, отмена и остановка. Обычная остановка кнопкой или по лимиту автоматически отправляет запись на ASR; отдельного шага «Распознать» нет. Пока идёт обработка — статус «Распознаём ответ…», после неё — редактируемый текст с «Верно, ответить», «Перезаписать» и локальным прослушиванием. Отмена, уход в фон, звонок и ошибка не отправляют незавершённую запись автоматически. Все tracks останавливаются на выходе, после остановки записи и при ошибке. Blob не кладётся в localStorage, IndexedDB или service worker.
3. Сервер проверяет CSRF/роль/владельца/версию/состояние, idempotency key, квоты, размер, сигнатуру контейнера и реальную длительность. Не доверять MIME/длительности из браузера. Декодирование ограничить временем и ресурсами; ошибочный файл не отправлять провайдеру.
4. Короткой транзакцией создаёт ход, резерв usage и lease. Отдельно вызывает допущенный ASR. Без D-02 внешний ASR не вызывается. Удаляет исходный временный файл в `finally`; периодический уборщик удаляет остатки после аварии.
5. Локально проверяет расшифровку на чувствительность/опасность до её постоянного хранения и любого последующего внешнего вызова. Критичный контент получает безопасный маршрут; неясный случай не передаётся как обычная учебная фраза. Проверки по словарю недостаточно: нужен допускаемый guard, протестированный на контексте и en/ru/kk.
6. Допустимая расшифровка возвращается для подтверждения; ASR-confidence опционален и не сравнивается одинаковым порогом между провайдерами. `unknown` не означает правильность. Тишина не должна превращаться в выдуманную реплику.
7. После «Верно»/ручной правки сервер повторно проверяет вход, строит минимальный контекст и вызывает TUTOR; входной/выходной guard не делит с генератором единственное самоодобрение.
8. Проверяет JSON, длины, допустимые цели/навыки, точность цитат и безопасность всех полей. При неопределённости показывает проверенный локальный шаблон. Не стримит сырой текст модели в браузер.
9. Короткой транзакцией принимает результат, обновляет прогресс/версию и наблюдения. Условие обновления включает текущую версию, lease и статус: если сессия уже завершена/удалена/отозвана, поздний ответ отбрасывается.
10. TTS запускается по отдельному нажатию только для принятой реплики. Ключ временного кэша включает хеш проверенного текста, голос, скорость и версию; доступ через авторизованный API. TTL ≤15 минут. Повтор в пределах кэша не делает новый внешний запрос; после истечения озвучка может потребовать новый учтённый вызов.

HTTPS/localhost требуется для доступа к микрофону. Поддержку кодека определять в рантайме. [MDN: getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia), [MDN: isTypeSupported](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/isTypeSupported_static).

## 4.7. Параллельность, повтор и восстановление

- Не держать транзакцию во время внешнего запроса. На одну сессию — одна активная операция генерации/помощи; блокировка в БД/optimistic lock, не только disabled-кнопка.
- Lease — 60 s при пределе запроса 45 s; по истечении операция становится failed через recovery-задачу. Перед принятием результата проверить действительность lease. Повторное принятие исключено unique constraints и проверкой статуса.
- После потери HTTP-ответа клиент читает сессию; повторяет тот же idempotency key только для того же действия/тела. Незавершённая операция возвращает 409 с `operation_in_progress` и возможностью перечитать состояние; завершённая — тот же ресурс.
- Сетевой повтор внутри адаптера допускается только для явно безопасного случая и в общем тайм-ауте. Не обещать exactly-once оплату внешнего API: при неизвестном исходе запроса провайдер мог списать средства. Это учитывается отдельным usage `unknown`, резерв не освобождается до сверки.
- Пользовательский повтор после зафиксированного failure — новая операция с новым ключом и бюджетным резервом, но той же подтверждённой учебной репликой. Она создаёт не более одного принятого результата.
- Finish/delete во время обработки помечают сессию закрытой; исходящий вызов по возможности отменяется, поздний результат не принимается, содержимое временных данных удаляется.

## 4.8. Контекст и правила движения по ситуации

Интерфейс отображает всю историю текущей сессии в хронологическом порядке: начальная реплика ИИ → подтверждённый ответ ученика → реакция/следующий вопрос ИИ и далее. Отображённый текст вопросов сохраняется, не вычисляется заново по номеру текущего хода. История имеет отдельную вертикальную прокрутку; при чтении старых сообщений появляется кнопка со стрелкой вниз «К свежему». Если ученик был в конце, новый ход прокручивается к свежему сообщению; иначе позиция чтения сохраняется. Изменение режима записи, открытие помощи и подтверждение текста не сбрасывают прокрутку. Ограничение модельного контекста ниже относится только к данным для TUTOR, а не к видимости реплик в интерфейсе.

Внешний TUTOR получает: системные инструкции, серверную карточку сценария с progression, сложность, язык пояснений, текущий вопрос, число содержательных ответов, максимум 4 последние допустимые пары реплик, до двух кодов ранее повторявшихся навыков и подтверждённый ответ. Полный профиль, ID, записи других занятий и необработанные блокированные реплики не передаются. Ранние факты не пересказываются отдельным свободным LLM-summary; произвольные сценарные слоты и внешние инструменты пока не реализованы.

Слоты содержат только учебные значения (например, `roomType=double`, `fictionalNights=2`), без реальных имён/контактов/адресов. Каждое значение имеет allowlist или предел; произвольный текст из речи не становится доверенной инструкцией.

Серверный порядок действий:

1. `support` → утверждённая поддерживающая пауза; никаких feedback/LLM-продолжений учебного сюжета.
2. `restricted`/личные секреты → короткое локальное ограничение или просьба использовать вымышленные данные; без сохранения цитаты.
3. `off_topic` → возврат к ситуации, `off_topic_streak + 1`; при втором подряд — кнопки продолжить/новая ситуация/закончить. Новый сценарий всегда новая сессия.
4. `clarify`/помощь → объяснение, тот же stage, без учебных ошибок; техническая помощь не расходует принятый ход.
5. `continue` → принять только допустимые предложения по целям/stage; максимум переход на соседний этап, не перескакивать к финалу.

Модель предлагает `goalCandidates` и stage; сервер проверяет их по карточке, виду ответа и лимитам. Это приблизительная учебная интерпретация, не доказательство знания. Завершение возможно после минимум 6 содержательных ответов и всех обязательных целей, обычно после 8; при 8 предложить заключительный вопрос, при 12 принятых ответах завершить независимо от желания модели. Ручное завершение всегда доступно.

## 4.9. Учебные наблюдения

### Отдельная таблица и граница владения

`speaking_observations` — обязательная таблица первой рабочей версии, а не JSON-поле профиля или технический лог. Одна строка соответствует одному замечанию по одному навыку в конкретном принятом ходе. Если в ответе два разных допустимых замечания, сохраняются две строки. Дополнительное создание общей таблицы всех ошибок DamuLab не требуется.

| Поле | Назначение |
| --- | --- |
| `student_profile_id` | Локальный ученик для выборки трудностей между его разговорами; наружу не передаётся |
| `session_id`, `turn_id` | Источник наблюдения; принадлежат тому же ученику, что и строка наблюдения |
| `skill_code` | Фиксированный учебный навык, например `grammar.past_simple`; тема беседы берётся из сессии |
| `kind` | Ошибка либо необязательный стилистический совет |
| `original`, `corrected`, `explanation` | Минимальный исходный фрагмент, исправление и причина; полный аудиофайл не хранится |
| `evidence` | Предположение, прошедшее технические проверки наблюдение либо оспоренное замечание; не обещает проверки методистом |
| `source`, `assisted` | Голос, текст, ручная правка и использованная помощь — для честной интерпретации |
| `created_at`, `expires_at` | Когда встречено замечание и когда его удалить |

Пример учебного факта: `original = Yesterday I go`, `corrected = Yesterday I went`, `skill_code = grammar.past_simple`, `kind = error`. Один такой факт означает «есть наблюдение», несколько независимых подходящих фактов — «повторяется трудность»; сам по себе он не доказывает незнание темы.

Внутри `kz.damulab.speaking`: entity/repository для наблюдений и `SpeakingFeedbackService` для их принятия, оспаривания и чтения повторяющихся трудностей. Только модуль speaking пишет и интерпретирует свои наблюдения. Допустимые внешние связи — общий профиль ученика и общая авторизация. Нет зависимости от школьных вопросов/оценок и нет записей в `answer_evaluations` или `skill_mastery`. Будущие сводные экраны обращаются к сервисному DTO модуля; не дублируют его формулу в своих запросах.

Сохранять замечания при принятии проверенного результата хода, не только при завершении всей сессии и не только при раскрытии блока исправления. Результат хода и наблюдения фиксируются одной транзакцией. При ошибке записи операция не объявляется принятой; повтор запроса не создаёт дубликатов. Проверять совпадение владельца у наблюдения, сессии и хода на сервере. Индекс для чтения трудностей: `(student_profile_id, skill_code, created_at)`.

### Как интерпретировать накопленные факты

Начальный справочник навыков:

```text
grammar.present_simple       grammar.past_simple
grammar.future               grammar.questions
grammar.present_continuous   grammar.present_perfect
grammar.articles             grammar.prepositions
grammar.word_order           grammar.agreement
grammar.comparatives         vocabulary.word_choice
grammar.negation             grammar.plural
grammar.verb_patterns
```

Нельзя добавлять динамические коды из LLM. Ситуация и навык — разные измерения: ошибка Past Simple может встретиться в фильме, магазине и выходных.

До двух замечаний на ответ. `original` должен буквально встречаться в подтверждённом тексте; исправление не меняет намерение и не добавляет факты. Без проверяемого фрагмента замечание отбрасывается до выходного guard. В live-режиме необязательные style-перефразировки отбрасываются после найденного изменения намерения ask → tell; формат kind=style сохранён для старых данных. Отсутствие обязательной классификации kind даёт `evidence=suggested`, без влияния на рекомендации.

Для статистики брать только `kind=error`, допустимый вход/выход, подтверждённую расшифровку, `evidence=confirmed`, без ручной правки и помощи. Здесь `confirmed` означает прохождение технических проверок и подтверждение текста учеником, а не методистскую верификацию лингвистической истины. Ученик может оспорить замечание; оно исключается из статистики.

Повторяющаяся трудность: минимум два подходящих наблюдения одного навыка в разных принятых ходах за последние 30 дней. Выбрать до двух навыков, совместимых с новой ситуацией, по числу повторений, затем по свежести. Отсутствие замечания не считается доказательством правильного применения, а повторение подсказки не повышает mastery. Проценты освоения и автоматическое изменение `skill_mastery` отсутствуют.

Сводка модуля возвращает код навыка, число подходящих независимых ходов, число разных сессий, дату последнего наблюдения и статус `observed`/`recurring`. Это частота обнаруженных ошибок, а не процент незнания: нет достоверного знаменателя всех случаев, когда ученик мог применить навык. Оспаривание, удаление или истечение TTL сразу меняют выборку. Стиль, ошибки распознавания, неподтверждённый текст и неопределённые замечания в эту сводку не входят.

Итог собирается локально: причина завершения, содержательные/все принятые ответы, фактическая длительность отправленного голосового материала, помощь, до трёх повторявшихся трудностей и подходящий следующий сценарий. Не выводить несуществующие успехи вроде «теперь ты знаешь Past Simple».

Реализация этапа 5: `summary` содержит acceptedAnswers, totalTurns, voiceAnswers (включая принятые записи с правкой), audioSeconds (с паузами), helpUses (null у исторических сессий до V70), до трёх difficulties и до двух nextFocus; nextScenarioCode предлагает повторить текущую ситуацию. Итог может показать единичное observed, не называя его повторяющимся. Для PAUSED_SUPPORT учебный итог и фокус не показываются. Активная беседа использует только наблюдения других сессий; следующий фокус завершённой — все допустимые наблюдения, включая эту сессию. Все производные вычисляются при чтении, поэтому оспаривание/удаление/TTL немедленно меняют рекомендации. [Полное описание этапа 5](INSIGHTS_IMPLEMENTATION.md).

## 4.10. Безопасность и приватность по умолчанию

Промпт — один слой. Дополнительно: серверный каталог/стадии, локальная проверка чувствительного входа, допущенный контент-guard, строгий контракт, проверка всех выходных полей, готовые fallback и проверка прав/квот. Guard обязан иметь независимый вызов/механизм; ответ `allow` внутри ответа TUTOR не используется как разрешение.

Выход — plain text с экранированием Thymeleaf/DOM `textContent`; HTML, скрипты и активные ссылки модели не исполняются. TTS принимает только утверждённую реплику из серверного результата, а не произвольный текст браузера. Нет инструментов поиска, отправки сообщений, бронирований и оплаты.

При сообщении о реальной опасности — локальный поддерживающий текст без запроса деталей и без обещания тайны/лечения. Не добавлять автоматически номера телефонов из LLM; локальные контакты допустимы только из отдельно проверенного источника и после отдельной реализации. Автоматическая отправка сообщений родителю/третьим лицам не входит в модуль.

`external-enabled=false` исключает также внешние вызовы guard и TTS. Нельзя при сбое безопасной локальной обработки отправить сырой текст внешнему guard «для проверки». Предварительная минимизация на сервере не гарантирует анонимность и не заменяет D-02. Проверка необходимых условий хранения проводится для каждого endpoint выбранного провайдера; отсутствие обучения на данных не приравнивать к отсутствию хранения. [OpenAI: управление данными API](https://developers.openai.com/api/docs/guides/your-data).

## 4.12. Мобильный клиент и жизненный цикл PWA

### Экран и управление

Основной экран — одна колонка: текущий вопрос, история по необходимости, раскрываемое исправление и крупное основное действие в нижней части. Действия доступны касанием, без hover и обязательного удержания пальца. Запись по схеме «нажать начать → нажать остановить»; главная кнопка отражает фактическое состояние.

Размеры действий — по NFR-19. Панель не закрывает текст и учитывает `env(safe-area-inset-bottom)`, динамическую высоту viewport и клавиатуру; `100dvh` применять с CSS-fallback. Не запрещать масштабирование. При редактировании расшифровки поле и кнопка подтверждения доступны над клавиатурой; при необходимости учитывать `visualViewport`, проверяя наличие API. Поворот экрана не сбрасывает ход и не запускает запись заново. [MDN: VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport).

### Захват и проигрывание

Определять `getUserMedia`, `MediaRecorder`, допустимые MIME и возможность реального старта записи в текущем режиме браузера/PWA. Даже положительный `isTypeSupported` не исключает ошибку записи: обрабатывать отказ/отзыв разрешения, занятое устройство и нехватку ресурсов. Не делать `Permissions API` обязательной предпосылкой: основная проверка — результат явного запроса микрофона. [MDN: isTypeSupported](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/isTypeSupported_static).

Перед записью остановить TTS/предпросмотр, освободить старые Blob URL и предыдущие tracks. Не держать микрофон включённым между ответами. Выбирать доступный сжатый mono-формат, если устройство поддерживает; параметры кодека — предпочтение, фактический размер/длительность проверяются отдельно.

Озвучка запускается явной кнопкой. После получения аудио проверять результат `audio.play()`; при запрете браузера показать «Нажми, чтобы воспроизвести», сохранив готовое аудио в пределах временного срока. Повторное нажатие не должно заново вызывать TTS без необходимости. Не полагаться на то, что пользовательский жест до сетевого запроса автоматически разрешит последующее проигрывание. [MDN: обработка отказа воспроизведения](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay).

### Сворачивание, звонок и возврат

Обрабатывать `visibilitychange`/`pagehide`: при полученном событии остановить захват и приостановить воспроизведение. Ошибка `MediaRecorder`, `track.ended` или прерывание track переводят локальный ответ в состояние «Запись прервана». Если удалось получить Blob, разрешить его прослушать/перезаписать; он не отправляется автоматически. Если данные утрачены — прямо предложить записать снова.

При `pageshow`/возврате в foreground сначала GET сессии, затем восстановить доступные действия. Не возобновлять микрофон или звук самостоятельно. Остановленная/отменённая операция не должна повторно отправляться только из-за события возврата. Принятый сервером результат важнее устаревшего состояния интерфейса.

Браузер может ограничить фоновые таймеры, а система — выгрузить страницу. Не рассчитывать на `beforeunload`, непрерывный фоновой JS или сохранность Blob в памяти после завершения процесса. Сырой голос не переносится в постоянное хранилище телефона ради восстановления. [MDN: Page Visibility и фоновые ограничения](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API).

### Сеть, офлайн и обновление PWA

При обрыве показывать этап и неопределённый результат отправки; после восстановления сначала перечитать сессию/ход, затем предложить повтор с соответствующим idempotency key. Не трактовать смену сети как новый ответ. Если Blob ещё в памяти, его можно повторно отправить по явному нажатию; после перезагрузки для неотправленного голоса нужна новая запись. Не обещать восстановление клиентского текстового черновика после выгрузки страницы, если он не был принят сервером.

В офлайне нет продолжения AI-диалога, записи «в очередь» и фонового sync аудио. Приватные ответы и аудио имеют `no-store` и не попадают в Cache Storage. Существующие исключения SW для `/student/**` и `/api/**` сохранить. Проверить обновление worker во время записи: не выполнять принудительный reload и не терять текущий ход; если в будущем понадобится обновление страницы, предложить его после завершения записи/сессии.

Полная матрица приёмки — Android Chrome/browser + PWA и iOS Safari/browser + PWA на физических устройствах. Отдельно проверить динамические панели, клавиатуру, громкоговоритель/наушники, разрешения, блокировку, звонок, сеть и возврат после выгрузки. Версии ОС/браузера и обнаруженные ограничения фиксировать в отчёте; desktop и эмулятор не заменяют эту приёмку.

## 4.13. Реализованное уточнение этапа 6

V71 добавляет `speaking_budget_accounts` (дневные USD-резервы, без цитат) и nullable provider_code/model_name/prompt_version в turns/generations. Снимок маршрута фиксируется до сети, старые данные остаются без выдуманного provenance. Turn DTO содержит requestId для сверки потерянного HTTP-ответа.

Резерв каждого облачного запроса фиксируется отдельной транзакцией под module-lock; ошибка и удаление истории не возвращают его. Неизвестная модель или исчерпанный резерв блокируют сеть. Значения по умолчанию — 3 USD/ученик/день и 20 USD/модуль/день; это резерв, не фактический инвойс. Пределы на JVM: пять облачных запросов, пять чтений аудио, два декодера. LLM timeout 12 секунд на этап, STT/TTS — 35 секунд. ADMIN получает только агрегаты в `/api/admin/speaking/operations` с no-store.

Текущая версия tutor/guard — tutor-v4. Отказ выходной проверки означает ошибку генерации без принятия хода, не нарушение со стороны ученика. Клиент после возврата/online сверяет серверную версию и requestId, не принимает потерянную запись за независимый текст. Подробные ключи, контракт метрик, ограничения и проверки — в [описании этапа 6](OPERATIONS_IMPLEMENTATION.md); подготовка образа/восстановления и открытые условия запуска — в [подготовке релиза](RELEASE_PREPARATION.md). Этот раздел уточняет фактическую реализацию, не закрывает целевую физическую и методистскую приёмку.
