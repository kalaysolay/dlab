# Недельные отчёты в Telegram

Реализация находится в ветке `feat/parent-telegram-reports`. HTML-макеты из отдельной
ветки не нужны для запуска: рабочий блок встроен в `/parent` и `/parent/profile`.

## Поведение

- Родитель нажимает «Подключить Telegram», затем «Начать» в боте. Ссылка одноразовая,
  действует 10 минут; в БД сохраняется только SHA-256 токена. Повторного подтверждения нет.
- Сразу включаются недельные отчёты по всем связанным детям, отдельно по каждому.
  По умолчанию — понедельник 09:00, Asia/Almaty (UTC+5).
- Родитель меняет день/время и включает/выключает подписку в кабинете. Команда `/stop`
  приостанавливает отправки; `/start` без новой привязки не включает их обратно.
- Подключённый Telegram нельзя автоматически перенести к другому родителю.
- Уже существующий флаг `weekly_parent_report_enabled` в профиле ученика соблюдается
  при подготовке и перед каждой отправкой. Нового выбора детей в кабинете родителя нет.
- Каждый отчёт и все ответы бота дублируются полностью: сначала казахский, затем русский.
  Настройки выбора языка нет. Поле language сохраняется для совместимости схемы.
- Отчёт охватывает предыдущую завершённую неделю в часовом поясе подписки: `[Пн 00:00, Пн 00:00)`.
  День отправки не меняет период. После простоя создаётся только последний период.
- В сообщении до трёх записей каждого вида на каждом языке, количество остальных и общие результаты.
  Полная версия сохраняется при подготовке и доступна по `/parent/reports/{id}` после входа
  только исходному родителю с действующей связью. Текст выводится с экранированием HTML.
- Завершённые лекции определяются по DONE/completed_at. Названия берутся из текущей
  версии лекции на момент подготовки отчёта. История названий на момент прохождения
  не восстанавливается. Результаты контрольных вопросов по лекции не сохраняются
  в существующем модуле (есть только факт успешной проверки), поэтому дроби X/Y
  для них не выдумываются. Тесты и викторины идут отдельными блоками.
- Для тестов и викторин учитываются все результаты периода; доля верных — сумма
  верных / сумма вопросов. Освоение навыков, длительность, сравнения разных заданий,
  ИИ-рекомендации и разговорная практика не включены.
- Отчёт начинается приветствием, именем ребёнка и периодом.
- Неделя без завершённых занятий тоже отправляется. V76 добавляет один факт посещения
  в день при успешном открытии ученической HTML-страницы: без URL, без содержания,
  без учёта фона/активов и без попыток считать офлайн-просмотры. Если посещения были,
  сообщение отличает их от завершённых занятий. «Посещения не зафиксированы» пишется
  только для недель, полностью покрытых новым учётом; для истории до его запуска
  прямо говорится, что полных данных о посещениях ещё нет.

## Включение на сервере

Для локальной проверки без публичного адреса: `TELEGRAM_REPORTS_ENABLED=true`,
`TELEGRAM_MODE=polling`, `TELEGRAM_BOT_USERNAME=damulab_bot`, токен через окружение.
Секрет webhook в polling не нужен. Если раньше был webhook, явно выполнить
`scripts/telegram/set-polling.ps1` — накопленные сообщения не удаляются.
Запускать только один poller на бота. При рестарте повтор последнего события безопасен
благодаря таблице update_id; offset продвигается после успешной обработки.
В polling входящий webhook закрыт. Кнопка полного отчёта появляется только при
HTTPS public-base-url: localhost с телефона родителя недоступен.
На проде остановить локальный poller, выставить `TELEGRAM_MODE=webhook` и
`APP_PUBLIC_BASE_URL=https://damulab.kz`, затем зарегистрировать webhook.

1. Создать отдельного бота через BotFather. Один бот обслуживает всех родителей.
2. Задать в окружении приложения:
   - `TELEGRAM_REPORTS_ENABLED=true`
   - `TELEGRAM_MODE=webhook`
   - `TELEGRAM_BOT_TOKEN` — секрет BotFather
   - `TELEGRAM_BOT_USERNAME` — имя без @
   - `TELEGRAM_WEBHOOK_SECRET` — случайный секрет из A–Z/a–z/0–9/_/-
   - `APP_PUBLIC_BASE_URL=https://<домен-Damulab>`
3. Выполнить обычный выпуск приложения: Flyway применит V75 и V76. Открыть HTTPS POST
   `/api/telegram/webhook` на reverse proxy, сохраняя заголовок X-Telegram-Bot-Api-Secret-Token.
4. Из окружения с этими секретами запустить `scripts/telegram/set-webhook.ps1`.
   Скрипт регистрирует webhook; приложение само регистрацию не меняет.
5. Подключить тестовый родительский аккаунт, проверить подтверждение, изменить расписание,
   получить отчёт и открыть его. Проверить `/stop` и возобновление из кабинета.

Без конфигурации блок подключения скрыт, фоновые отправки выключены. Секреты не
коммитить, адрес Bot API с токеном не логировать. Настоящие сообщения из тестов не отправляются.

## Очередь и диагностика

`parent_report_deliveries` хранит снимок, попытки, безопасный код ошибки и message_id.
Уникальность `(parent_id,student_id,week_start)` не позволяет повторно поставить неделю.
`link_id` защищает от отправки после отвязки/повторной привязки; удаление связи удаляет
связанные снимки. Перед отправкой проверяются подписка, поколение подключения, связь
и активность обоих аккаунтов. Остановка отменяет ожидающие сообщения.

Отправщик имеет отдельный поток, чтобы ожидание Telegram не задерживало викторины.
Подписка блокируется на короткий сетевой вызов (таймаут 12 секунд): уже начавшееся
сообщение может дойти при одновременном отключении, последующие отменяются.
При 429 учитывается retry_after, при 5xx — задержка; максимум пять попыток.
403 отключает получателя до повторного подключения после разблокировки бота.
Повторы не переживают границу актуальности периода (следующий понедельник).

Статусы: PENDING, SENDING, SENT, CANCELLED, FAILED, UNKNOWN. SENT означает приём
Telegram, не прочтение. Сетевая ошибка даёт UNKNOWN без автоматического повтора;
аварийное завершение во время HTTP оставляет SENDING. Это сознательный выбор против
дублирования: оператор проверяет такие строки, автоматической «точно однократной»
доставки Bot API не обещает. Не переводить их массово в PENDING.

Ограничения: входящие подтверждения подключений отправляются без очереди, при их
сетевой ошибке состояние подключения всё равно сохраняется. Это видно в кабинете.
WhatsApp не подключён; расчёт отделён от Telegram, чтобы добавить другой транспорт позже.

Официальные протоколы: https://core.telegram.org/bots/features#deep-linking,
https://core.telegram.org/bots/api#setwebhook, https://core.telegram.org/bots/faq.
