# Локальная БД с идентификаторами PROD

Для импорта вопросов и лекций локальная БД может использовать тот же учебный
справочник и те же первичные ключи, что и PROD. Синхронизация переносит только:

- `subjects`;
- `grades`;
- `topics`;
- `atomic_skills`;
- `topic_ai_examples`.

Аккаунты, профили, телефоны, токены, прогресс учеников, логи и другие
пользовательские или операционные данные в слепок не попадают.

## 1. Создать слепок на PROD

На VPS после обновления репозитория:

```bash
sudo chmod +x /opt/damulab/deploy/export-reference-data.sh
sudo bash /opt/damulab/deploy/export-reference-data.sh
```

Скрипт создаст файл вида
`/var/backups/damulab/reference-data-20261001T120000Z.dump`, выставит права
`600` и напечатает SHA-256. Файл нужно скопировать на рабочую машину обычным
защищённым способом, например `scp`.

## 2. Восстановить локально

Сначала обновить локальный код до версии, которая развёрнута на PROD, и хотя бы
один раз запустить приложение, чтобы Flyway создал локальную схему. Затем из
корня репозитория выполнить. Если приложение запущено из IDE или через
`gradlew bootRun`, сначала остановить его; Docker-контейнер `app` скрипт
останавливает и запускает сам.

```powershell
.\scripts\restore-prod-reference-data.ps1 `
  -DumpPath C:\path\to\reference-data-20261001T120000Z.dump `
  -Force
```

Если Docker Compose запускается с отдельным env-файлом:

```powershell
.\scripts\restore-prod-reference-data.ps1 `
  -DumpPath C:\path\to\reference-data.dump `
  -EnvFile .env `
  -Force
```

Скрипт:

1. запускает локальный PostgreSQL;
2. проверяет, что архив содержит все ожидаемые таблицы;
3. сохраняет полный локальный backup в `backups/local-db/`;
4. останавливает локальное приложение, если оно было запущено;
5. заменяет учебный справочник, сохраняя PROD ID;
6. корректирует identity sequences и снова запускает приложение.

Скрипт работает с PostgreSQL из `docker-compose.yml`. При запуске приложения
из IDE или через Gradle нужно направить его в ту же БД (значения должны
совпадать с `.env`, если он используется):

```powershell
$env:DB_URL="jdbc:postgresql://localhost:5432/damulab"
$env:DB_USERNAME="damulab"
$env:DB_PASSWORD="damulab"
.\gradlew.bat bootRun
```

## Важно

Синхронизация очищает локальные вопросы, лекции, тестовые сессии и другие
таблицы, которые зависят от заменяемого справочника. Это намеренное поведение:
после синхронизации получается чистая среда для проверки повторяемого импорта.

Перед очисткой всегда создаётся backup. Для постоянной работы удобнее выделить
отдельную локальную БД, например `damulab_prodlike`, через `POSTGRES_DB`/`DB_URL`,
а личную тестовую БД не синхронизировать.

После запуска приложения локальные demo-пользователи создаются обычным
`DemoUserSeeder`; пароль PROD в локальную среду не переносится.
