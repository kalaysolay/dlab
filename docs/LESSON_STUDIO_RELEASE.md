## Включено и исключено

Включены studio capabilities/lookup/sync, externalId, условная запись, обратное чтение; отдельный publish API; renderer/CSS 2.0.1, расширения Quill, санитаризация HTML и YouTube; сохранение опубликованной версии при правке черновика; AI composer только для блочного режима формул; 404 вместо 500 при прямом ученическом запросе черновика; регрессионные тесты и QA-инструменты.

Наличие publish API не разрешает публикацию. Изменения переводчика, quiz draft answers/V66, локальные БД, хранилища, ключи, cookies, `.local` и учебные пакеты не включаются в серверный JAR. Speaking и действующие AI-маршруты сохраняются из production-базы.

## Проверки

Отдельный Linux-стенд использует профиль prod, PostgreSQL 16.15, Temurin 21.0.13+9, nginx 1.18.0, собственные хранилища и аккаунты. Сначала запускается считанный production JAR; все 68 строк Flyway должны совпасть с продом. После локального backup запускается кандидат. Байты применённых миграций и speaking-классов сравниваются с production JAR.

HTTPS-клиент доверяет отдельному сертификату только внутри Node-процесса через NODE_EXTRA_CA_CERTS; системное доверие не меняется. Браузерная проверка использует отдельный HTTP localhost-порт с корректными forwarded headers. Это явное отличие от production TLS-браузера. Внешние AI/почта/push выключены; OAuth/voice и физический телефон не объявляются проверенными.

`node scripts/lesson-studio-qa/transfer.mjs <run> upload` проверяет два пилота, RU/KK и повтор без дубликата; `after-admin` сверяет сохранение, `conflict` проверяет отказ следующей записи. Утилита ограничена localhost и не содержит публикации. Доступ: `access.mjs`; JAR: `verify-jar.ps1`.

Пилоты остаются черновиками до отдельного разрешения. Полную предметную приёмку пользователя и реальный ученический просмотр пилотов нельзя заменять автоматическими тестами синтетических опубликованных фикстур. На проде нет предмета «История Казахстана»: он и тема пилота созданы только на тесте. Перед рабочим переносом потребуется отдельная настройка справочника.
