# Правила генерации вопросов для Damulab

Этот файл — обязательная инструкция для агента, который создаёт новые вопросы по материалам учебника. Результат должен одновременно соответствовать содержанию учебника и техническому контракту Damulab.

## Задача агента

Агент использует учебник как источник фактов, терминологии, уровня сложности и примеров оформления, но создаёт **новые** вопросы. Нельзя механически копировать упражнение и менять в нём одно число.

Перед генерацией агент должен:

1. Определить тему, класс и проверяемый навык по предоставленному фрагменту учебника.
2. Посмотреть, как в учебнике сформулированы объяснения и задания этого уровня.
3. Создать новый вопрос в пределах изученного материала.
4. Самостоятельно решить вопрос и проверить ключ ответа.
5. Убедиться, что версии RU и KK проверяют одно и то же: числа, условия, варианты и правильные ответы должны совпадать по смыслу.
6. Проверить результат по чек-листу в конце этого файла.

Если учебник не даёт достаточно информации для достоверного вопроса, не выдумывать факт. Добавить понятный флаг в `flags` и снизить `qualityScore` либо не создавать такой вопрос, если вызывающая инструкция это допускает.

## Формат результата

Ответ агента — только валидный JSON в UTF-8. Нельзя добавлять Markdown-ограждение (` ```json `), пояснения до JSON или текст после JSON.

Корневой элемент всегда объект с единственным полем `questions`:

```json
{
  "questions": [
    {
      "questionType": "SCQ",
      "difficulty": 2,
      "bodyRu": "Какая обыкновенная дробь равна 0,5?",
      "bodyKk": "Қай жай бөлшек 0,5 санына тең?",
      "explanationRu": "Десятичная дробь 0,5 означает пять десятых: 5/10 = 1/2.",
      "explanationKk": "0,5 ондық бөлшегі оннан бесті білдіреді: 5/10 = 1/2.",
      "source": "Учебник из входных данных, раздел «Десятичные дроби»; новый вопрос по материалу раздела",
      "options": [
        {"label": "A", "textRu": "1/2", "textKk": "1/2", "correct": true},
        {"label": "B", "textRu": "1/4", "textKk": "1/4", "correct": false},
        {"label": "C", "textRu": "3/4", "textKk": "3/4", "correct": false}
      ],
      "matchingPairs": [],
      "fillAnswers": [],
      "qualityScore": 96,
      "qualityNotes": "Ответ пересчитан; формулировки и варианты RU/KK совпадают по смыслу.",
      "flags": []
    }
  ]
}
```

Использовать имена полей **точно** как в примере, в `camelCase`. Не использовать `question_type`, `body_ru`, `matching_pairs`, `fill_answers`, `match_mode` и другие варианты имён.

Создать ровно столько элементов, сколько запросила вызывающая инструкция. Если запрошен конкретный тип, `questionType` каждого элемента должен совпадать с ним; нельзя подменять тип более удобным.

Каждый объект вопроса обязан содержать все поля из примера. Для неиспользуемого типа ответа передавать пустой массив `[]`, а не `null` и не пропускать поле:

| Тип | `options` | `matchingPairs` | `fillAnswers` |
| --- | --- | --- | --- |
| `SCQ` | заполнить | `[]` | `[]` |
| `MCQ` | заполнить | `[]` | `[]` |
| `MATCHING` | `[]` | заполнить | `[]` |
| `FILL_IN` | `[]` | `[]` | заполнить |

### Общие поля вопроса

- `questionType` — одно из четырёх значений: `SCQ`, `MCQ`, `MATCHING`, `FILL_IN`.
- `difficulty` — целое число от `1` до `5`.
- `bodyRu` и `bodyKk` — непустые формулировки одного вопроса на русском и казахском языках.
- `explanationRu` и `explanationKk` — решение или объяснение, почему ключ ответа верен. Не ограничиваться фразой «правильный ответ — B».
- `source` — непустая проверяемая ссылка на входной материал: название/идентификатор учебника, раздел или параграф и страница, если они известны. Не придумывать номер страницы. Для нового задания явно можно указать «создано по материалу/образцу», чтобы не выдавать его за дословную цитату.
- `qualityScore` — целое число от `0` до `100`, честная самооценка готовности вопроса.
- `qualityNotes` — краткая запись о проверках: корректность решения, соответствие теме, согласованность RU/KK и отсутствие двусмысленности.
- `flags` — массив строк с рисками для методиста, например `source_page_not_provided`, `translation_needs_review`, `ambiguous_wording` или `regexp_needs_review`. Если известных рисков нет, передать `[]`.

Не включать в результат внутренние `subjectId`, `topicId`, `gradeId`, `studentId` и другие ID. Не включать имена учеников, телефоны, email, ключи доступа и другие персональные или секретные данные.

## Типы вопросов

### `SCQ` — один правильный вариант

В `options` должно быть минимум два варианта и **ровно один** вариант с `"correct": true`.

Каждый вариант содержит:

```json
{
  "label": "A",
  "textRu": "Текст варианта на русском",
  "textKk": "Қазақ тіліндегі нұсқа",
  "correct": false
}
```

Правила:

- Использовать уникальные метки `A`, `B`, `C`, `D` и далее без пропусков.
- Все варианты должны быть правдоподобными и относиться к одному вопросу.
- Не подсказывать ответ длиной, грамматикой, повтором слов из условия или явно абсурдным дистрактором.
- Варианты RU и KK с одинаковой меткой должны иметь одинаковый смысл.
- Если правильных вариантов несколько, использовать `MCQ`, а не `SCQ`.

### `MCQ` — несколько правильных вариантов

Формат `options` такой же, как у `SCQ`. Технически система требует минимум два варианта и минимум один `correct=true`. Методическое правило: для `MCQ` создавать не менее двух правильных вариантов; если правильный вариант один, использовать `SCQ`.

Формулировка должна явно предупреждать ученика о множественном выборе: например, «Выберите все верные утверждения» / «Барлық дұрыс тұжырымдарды таңдаңыз».

Набор `correct=true` должен быть одинаково верен для RU и KK. Нельзя делать вариант частично верным или зависящим от неоговорённого допущения.

### `MATCHING` — установление соответствий

В `matchingPairs` должно быть минимум две полные пары. Рекомендуется от 3 до 6 пар, чтобы задание было содержательным и оставалось удобным в интерфейсе.

Одна строка массива — одна правильная пара:

```json
{
  "leftRu": "50%",
  "leftKk": "50%",
  "rightRu": "0,5",
  "rightKk": "0,5"
}
```

Ключ соответствия определяется **позицией в объекте пары**: `leftRu` соответствует `rightRu`, а `leftKk` — `rightKk` в той же строке. Правая колонка перемешивается системой при показе ученику; агент не должен перемешивать правильные пары самостоятельно.

Обязательные правила `MATCHING`:

- У каждой пары заполнены все четыре поля: `leftRu`, `leftKk`, `rightRu`, `rightKk`.
- Пара RU и пара KK выражают одно и то же соответствие.
- Значения слева уникальны, значения справа также уникальны. Задание должно задавать взаимно однозначное соответствие.
- Не создавать значения, которые после нормализации становятся одинаковыми. Например, `0,5` и `0.5` система считает одинаковыми; различия только в регистре или лишних пробелах тоже не различают элементы.
- Не добавлять ручную нумерацию (`1.`, `2.`) или буквы к значениям: интерфейс сам отображает элементы.
- Не включать в правую часть два равноправных ответа для одного левого элемента.
- Формулировка `bodyRu`/`bodyKk` должна прямо просить установить соответствие.

Полный пример:

```json
{
  "questionType": "MATCHING",
  "difficulty": 2,
  "bodyRu": "Соотнесите дробь и равное ей десятичное число.",
  "bodyKk": "Бөлшекті оған тең ондық санмен сәйкестендіріңіз.",
  "explanationRu": "Чтобы получить десятичную запись, нужно разделить числитель на знаменатель: 1/2 = 0,5; 1/4 = 0,25; 3/4 = 0,75.",
  "explanationKk": "Ондық жазуды алу үшін алымды бөлімге бөлеміз: 1/2 = 0,5; 1/4 = 0,25; 3/4 = 0,75.",
  "source": "Учебник из входных данных, раздел «Дроби»; новый вопрос по материалу раздела",
  "options": [],
  "matchingPairs": [
    {"leftRu": "1/2", "leftKk": "1/2", "rightRu": "0,5", "rightKk": "0,5"},
    {"leftRu": "1/4", "leftKk": "1/4", "rightRu": "0,25", "rightKk": "0,25"},
    {"leftRu": "3/4", "leftKk": "3/4", "rightRu": "0,75", "rightKk": "0,75"}
  ],
  "fillAnswers": [],
  "qualityScore": 94,
  "qualityNotes": "Все пары однозначны; вычисления и версии RU/KK сверены.",
  "flags": []
}
```

### `FILL_IN` — заполнение пропусков

Пропуск в тексте обозначается только меткой вида `[[1]]`, `[[2]]`, `[[3]]`. Интерфейс распознаёт числовые метки именно в таком виде.

Для каждого пропуска из `bodyRu` и `bodyKk` должен существовать ровно один объект в `fillAnswers`:

```json
{
  "placeholder": "[[1]]",
  "answer": "30",
  "matchMode": "NUMERIC_TOLERANCE",
  "tolerance": 0.01
}
```

Обязательные правила `FILL_IN`:

- Нумеровать пропуски подряд с `[[1]]`, без пропусков и повторов.
- Одинаковый набор меток должен присутствовать в `bodyRu` и `bodyKk`.
- Каждая метка встречается ровно один раз в каждой языковой версии вопроса.
- Порядок и смысл пропусков в RU и KK совпадают.
- `placeholder` в `fillAnswers` посимвольно совпадает с меткой в тексте.
- Все `placeholder` уникальны; одна метка не может иметь несколько альтернативных объектов ответа.
- В `answer` хранить только то, что ученик должен ввести. Единицу измерения лучше написать после пропуска в `bodyRu`/`bodyKk`, а не включать в числовой ответ.
- `answer` всегда строка, даже если ответ является числом.
- `matchMode` — точное имя одного из режимов ниже. Поле `mode` не поддерживается AI-контрактом.

#### Режимы проверки `matchMode`

`EXACT`

- Сравнение с учётом регистра и внутренних пробелов.
- Пробелы только по краям ответа игнорируются.
- Использовать для коротких ответов с единственным допустимым написанием: символа, формулы, кода или строго заданного термина.
- Для обычного слова чаще безопаснее `NORMALIZED`.
- `tolerance` должен быть `null`.

`NORMALIZED`

- Система убирает пробелы по краям, приводит буквы к нижнему регистру, схлопывает несколько пробелов в один и считает десятичную запятую и точку эквивалентными.
- Использовать для слов и коротких фраз, где регистр и случайные пробелы не должны влиять на результат.
- Система не исправляет опечатки, не меняет падежи и не принимает синонимы.
- `tolerance` должен быть `null`.

`NUMERIC_TOLERANCE`

- `answer` должен быть строкой с одним числом, например `"30"` или `"3.14"`.
- `tolerance` обязателен, задаётся JSON-числом и не может быть отрицательным.
- Ответ верен, если абсолютная разница с эталоном не больше `tolerance`.
- Ученик может использовать точку или запятую как десятичный разделитель.
- Не включать единицы измерения, проценты, формулы или слова в `answer`: они не преобразуются в число.
- Не назначать произвольный большой допуск. Выбрать его из требуемой точности задачи; для целого точного ответа обычно достаточно `0`, для результата до сотых — часто `0.01`.

`REGEXP`

- `answer` содержит регулярное выражение Java, а не обычный текст.
- Проверяется вся строка ответа без учёта регистра; пробелы по краям предварительно удаляются.
- Обратный слеш в JSON нужно удваивать: например, регулярное выражение `\d+` записывается как `"\\d+"`.
- Использовать только когда заранее известен ограниченный набор корректных форм записи, который нельзя покрыть `NORMALIZED`.
- Не использовать чрезмерно широкие выражения вроде `.*` и сложные конструкции с риском долгой обработки.
- `tolerance` должен быть `null`, а в `flags` рекомендуется добавить `regexp_needs_review`.

Пример с двумя числовыми пропусками:

```json
{
  "questionType": "FILL_IN",
  "difficulty": 2,
  "bodyRu": "Вычислите: 15% от 200 равно [[1]], а 25% от 80 равно [[2]].",
  "bodyKk": "Есептеңіз: 200 санының 15%-ы [[1]], ал 80 санының 25%-ы [[2]].",
  "explanationRu": "15% от 200: 200 × 0,15 = 30. 25% от 80: 80 × 0,25 = 20.",
  "explanationKk": "200 санының 15%-ы: 200 × 0,15 = 30. 80 санының 25%-ы: 80 × 0,25 = 20.",
  "source": "Учебник из входных данных, раздел «Проценты»; новый вопрос по материалу раздела",
  "options": [],
  "matchingPairs": [],
  "fillAnswers": [
    {"placeholder": "[[1]]", "answer": "30", "matchMode": "NUMERIC_TOLERANCE", "tolerance": 0},
    {"placeholder": "[[2]]", "answer": "20", "matchMode": "NUMERIC_TOLERANCE", "tolerance": 0}
  ],
  "qualityScore": 96,
  "qualityNotes": "Оба ответа пересчитаны; метки уникальны и совпадают в RU/KK.",
  "flags": []
}
```

## Содержательные требования

- Вопрос проверяет один понятный навык либо явно связанный набор действий.
- В условии достаточно данных для единственного ключа ответа.
- Факты и термины подтверждаются входным учебником.
- Сложность соответствует классу и полю `difficulty`:
  - `1` — прямое воспроизведение знания или одно простое действие;
  - `2` — применение знакомого правила;
  - `3` — несколько связанных действий;
  - `4` — перенос знания или нетривиальный анализ;
  - `5` — сложная составная задача в пределах программы.
- Не создавать вопрос, зависящий от изображения, таблицы или схемы, если этот материал не передаётся вместе с вопросом и не описан в тексте.
- Не использовать формулировки «всё перечисленное», «ничего из перечисленного» и отрицание в отрицании.
- Не делать вопрос двусмысленным ради повышения сложности.
- Не добавлять сведения, которых нет в учебнике, только потому что они кажутся общеизвестными.
- Объяснение должно подтверждать именно заданный ключ, а не обсуждать тему в целом.
- Новый вопрос не должен дословно воспроизводить эталон из учебника, если вызывающая инструкция явно не требует цитирования.

## Самопроверка перед ответом

Перед выдачей JSON агент обязан проверить:

1. Корень имеет вид `{"questions":[...]}` и массив не пуст.
2. JSON синтаксически валиден, без комментариев, Markdown и лишних полей.
3. У каждого вопроса есть все обязательные поля; имена полей записаны в `camelCase`.
4. `questionType` входит в `SCQ`, `MCQ`, `MATCHING`, `FILL_IN`; `difficulty` находится в диапазоне `1..5`; `qualityScore` — в диапазоне `0..100`.
5. `bodyRu`, `bodyKk` и `source` не пусты.
6. RU и KK содержат одинаковые исходные данные и приводят к одному ключу.
7. Используется только один соответствующий типу массив ответа, остальные массивы пусты.
8. Для `SCQ` есть ровно один правильный вариант; для `MCQ` — минимум один, а по методическому правилу минимум два.
9. Для `MATCHING` есть минимум две полные, уникальные и однозначные пары.
10. Для `FILL_IN` метки вида `[[N]]` совпадают в обоих текстах и один к одному соответствуют `fillAnswers`; режимы и `tolerance` заполнены корректно.
11. Правильный ответ независимо пересчитан или перепроверен по учебнику.
12. `source`, `qualityNotes` и `flags` честно отражают происхождение и известные риски вопроса.

Если хотя бы одна проверка не пройдена, исправить вопрос до формирования окончательного JSON.
