# Ускорение запуска и результатов викторин

Ветка `perf/quiz-start-results` создана от `main` (`75018d0`).

## Изменения

- Завершённая игра показывает результаты в текущей странице и меняет адрес через `history.replaceState`. Повторная загрузка HTML больше не нужна.
- Прямое открытие `/results` проверяет участие и статус комнаты, не рассчитывая разбор до отдельного запроса API. Завершение расписания по-прежнему сохраняет итог атомарно.
- Кнопка повтора загружается после отображения результата отдельным HTML-фрагментом. Она проверяет актуальную публикацию одной игры и читает только её банк. Сбой фрагмента оставляет ссылку на каталог и не меняет результат.
- Параметры классов загружаются только для комнаты ожидания.
- `countUpTo` отделяет достаточность контента от сборки раундов и прекращает проверку при достижении нужного числа пригодных источников. При нехватке возвращается фактическое количество.
- Словарный `GamePool` один раз на транзакцию проверяет полноту и аудиторию слов, индексирует переводы, альтернативы и симметричные запреты. Проверка слова заканчивается на трёх безопасных вариантах. Полные списки вариантов и их сортировка нужны только выбранным раундам.

Окончательный набор фиксируется при старте в прежней транзакции с блокировкой комнаты. Между запросами данные не кешируются. Изменение публикаций, аудитории или правил учитывается при следующей проверке. Таймер последнего вопроса, правила начисления баллов, история и проверка доступности при создании новой комнаты сохранены.

## Метод замера

`QuizStudentUiIntegrationTest.quizLatencyProbe` создаёт синтетические опубликованные банки: 100 фактов, 100 слов и один предметный SCQ-вопрос; одна игра содержит один раунд. Кроме них присутствует стартовый каталог из миграций. Для каждой механики выполняются четыре одинаковые последовательности: старт, чтение состояния, завершение расписания, HTML результатов, API результатов. Первый замер исключается; сравнивается медиана оставшихся трёх. После изменения отдельно измеряется фрагмент повтора.

Время — длительность серверной операции в локальной JVM; `sql` — число подготовленных SQL-выражений Hibernate, включая служебные запросы и запись. Это не браузерное время и не отдельное время исполнения SQL. Скорость production, влияние сети и поведение больших групп этим замером не установлены. В тестах нет нестабильных порогов времени.

## Проверки

- Контракт словарного индекса сравнивается с полной редакционной диагностикой на смешанном банке: альтернативы, дубли переводов, классы, межнаборные варианты, неподтверждённые слова и запреты.
- Проверяется достаточность и точное число при нехватке; сохраняется случайный выбор равноприоритетных вариантов.
- Интеграционные проверки результатов запрещают загрузку сущностей банков при рендере страницы; фрагмент повтора не должен читать банки других механик.
- Проверяются чужое участие, доступ до завершения, CSRF формы повтора, скрытая игра, соответствие карточки повтора карточке каталога, исторические результаты и все предметные форматы.
- DOM-проверка подтверждает переход к результатам без перезагрузки и отображение итога при зависшем или ошибочном запросе повтора.
