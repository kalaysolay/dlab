# Damulab: seed-вопросы из первоисточника

Генерация **начального** банка вопросов в Cursor → файлы в `content/seed/`.
Не писать сразу в продовую БД. Id (`subjectId`, `topicIds`, `gradeIds`) подставляются при импорте позже.

Полный текст промпта и пример JSON: [content/prompts/question-seed-generation.md](../../../content/prompts/question-seed-generation.md).
Схема полей: [schema.md](schema.md).

## Перед генерацией — собрать бриф

Если чего-то нет — **спросить**, не угадывать. Обязательно:

| Поле | Зачем |
|------|--------|
| `subjectRu` / `subjectKk` | Предмет (тон, термины) |
| `gradeNo` | Аудитория: лексика, длина формулировок, допустимая абстракция |
| `topicRu` / `topicKk` | Границы содержания |
| `topicSlug` | Имена файлов (латиница kebab-case) |
| `source` | Путь к PDF / parsed JSON / вставка фрагмента — **единственная** база фактов |
| `count` | Обычно 10–15 на тему |

Желательно:

| Поле | Зачем |
|------|--------|
| `atomicSkillRu` / `atomicSkillKk` | Узкий навык внутри темы |
| `preferredTypes` | `mix` или список `SCQ,MCQ,FILL_IN,MATCHING` |
| `difficultyMix` | Иначе дефолт ~20% 1–2 / 50% 3 / 30% 4–5 |
| `methodistInstruction` | Особые ограничения методиста |
| `illustrationPolicy` | См. ниже; **по умолчанию `none`** |

### Аудитория (класс)

Подстраивай формулировки под `gradeNo`:

- **1–4**: короткие предложения, бытовые примеры, без лишней абстракции; KK — простой школьный язык.
- **5–7**: можно 2–3 шага рассуждения, аккуратные термины из источника.
- **8–11**: допускай более плотные формулировки и символику, всё ещё школьный тон.

Не завышай сложность «для галочки»: `difficulty` должна соответствовать реальной когнитивной нагрузке для этого класса.

### Языки

Каждый вопрос — **полная** пара RU/KK:

- `bodyRu` ↔ `bodyKk` — тот же смысл и та же сложность
- варианты / пары / объяснения — тоже оба языка
- KK: естественный школьный казахский (кириллица), не дословный калька с RU
- не смешивать языки внутри одного поля

## Иллюстрации — только явно

**По умолчанию иллюстраций нет** (`illustrationPolicy: none`).

Не добавляй рисунки «на всякий случай». Примеры тем **без** картинок, если пользователь не просил иное:

- деление/умножение на 10, 100, 1000
- проценты «найди N% от числа»
- порядок действий, простые уравнения текстом
- определения и факты без схемы

`illustrationPolicy`:

| Значение | Поведение |
|----------|-----------|
| `none` | У всех `needsIllustration: false`, нет `{{IMG:…}}`, `imageJobs: []` |
| `explicit` | Картинки **только** для `localId` / условий из брифа (`illustrationFor`) |
| `visual-topics` | Разрешено предложить картинки лишь где без рисунка задание **неполное** (геометрия, график, чертёж, карта, схема из учебника). Спросить подтверждение, если в брифе не сказано |

Если пользователь пишет «с иллюстрациями» без деталей — уточни: ко всем, к каким `localId`, или только к визуальным типам заданий.

Когда иллюстрация разрешена для вопроса:

- `needsIllustration: true`
- маркер `{{IMG:filename.png}}` в **обоих** body
- `illustration.prompt` без спойлера ответа
- запись в `imageJobs`
- файл позже: `content/seed/{gradeNo}/{topicSlug}/images/`

## Рабочий процесс

1. Прочитать бриф + первоисточник (файл/фрагмент). Не выдумывать факты вне источника.
2. Сверить `illustrationPolicy` (дефолт `none`).
3. Сгенерировать JSON по схеме из [schema.md](schema.md) / промпта.
4. Сохранить:
   - `content/seed/{gradeNo}/{topicSlug}/questions.json`
   - при необходимости список image jobs (в том же JSON)
5. Кратко отчитаться по-русски: сколько вопросов, типы, сложности, сколько иллюстраций и почему.

Не коммить и не импортировать в БД, пока пользователь не попросит.

## Типы и ключи ответа

- **SCQ** — ровно 1 `correct: true`, ≥3 вариантов (лучше 4)
- **MCQ** — ≥1 correct, ≥3 вариантов
- **MATCHING** — ≥3 пары
- **FILL_IN** — плейсхолдеры `[[1]]`… + `fillAnswers` (`EXACT` \| `NORMALIZED` \| `NUMERIC_TOLERANCE` \| `REGEXP`)

`difficulty` 1..5 оценивай по заданию (не копируй одно число на всю пачку).

## Чего не делать

- Не ставить `subjectId` / `topicIds` / `gradeIds` в seed
- Не генерировать картинки/бинарники в этом скилле (только ТЗ в `imageJobs`, если policy разрешил)
- Не публиковать в prod и не обходить review
- Не копировать длинные абзацы учебника дословно — переформулировать в задание
